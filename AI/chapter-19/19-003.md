# RTX 3080 可运行的开源 LLM

这里按“一个公司选一个相对热门、适合 RTX 3080 本地跑的开放权重模型”整理。

RTX 3080 常见是 10GB 或 12GB 显存，所以更适合 7B-14B 模型。20B 模型通常要 Q4 量化，并且需要控制上下文长度；30B/32B 以上模型即使能通过 CPU offload 跑起来，速度也会明显下降。

## 推荐模型

| 公司 | 推荐模型 | 大小 | RTX 3080 可跑建议 | 运行方式 | 适合场景 |
|------|----------|------|-------------------|----------|----------|
| OpenAI | `gpt-oss-20b` | 20B / MoE | 勉强可跑，建议 Q4、短上下文；10GB 显存可能需要 CPU offload | `ollama run gpt-oss:20b` | 推理、Agent、工具调用、通用问答 |
| Meta | `Llama 3.1 8B` | 8B dense | 很适合，Q4/Q5/Q8 都可以试 | `ollama run llama3.1:8b` | 通用问答、英文、代码、轻量 Agent |
| Qwen | `Qwen3-14B` | 14B dense | 可以跑，建议 Q4；中文体验较好 | `ollama run qwen3:14b` | 中文、代码、推理、Agent |
| DeepSeek | `DeepSeek-R1-Distill-Qwen-14B` | 14B dense | 可以跑，建议 Q4；推理时输出较长，要控制上下文 | `ollama run deepseek-r1:14b` | 数学、代码、复杂推理 |
| Google | `Gemma 4 12B` | 12B dense | 很适合，Q4/Q5 较稳 | `ollama run gemma4:12b` | 多模态、通用问答、轻量部署 |
| Microsoft | `Phi-4` | 14B dense | 可以跑，Q4 较稳；12GB 显存体验更好 | `ollama run phi4` | 小模型高质量推理、代码、低延迟 |

## RTX 3080 12GB 实测结果

测试机器：

- GPU：NVIDIA GeForce RTX 3080，12GB 显存
- 系统：Windows，通过 SSH 远程执行
- 运行框架：Ollama 0.32.5
- 模型目录：`D:\ollama\models`
- 默认上下文：4096 tokens

实测结论：下面几个模型都能在 3080 12GB 上跑起来。其中 8B-14B 模型基本可以全 GPU 加载；`gpt-oss:20b` 也能跑，但需要一部分 CPU offload。

| 模型 | Ollama 名称 | 下载大小 | 运行结果 | 显存/加载情况 |
|------|-------------|----------|----------|---------------|
| OpenAI gpt-oss 20B | `gpt-oss:20b` | 13GB | 成功 | 约 9.7GB 在 GPU，约 3.4GB 在主机内存，属于混合加载 |
| Meta Llama 3.1 8B | `llama3.1:8b` | 4.9GB | 成功 | 全 GPU，预计约 5.0GB 显存 |
| Qwen3 14B | `qwen3:14b` | 9.3GB | 成功 | 全 GPU，预计约 9.2GB 显存 |
| DeepSeek-R1-Distill-Qwen 14B | `deepseek-r1:14b` | 9.0GB | 成功 | 全 GPU，预计约 9.0GB 显存 |
| Google Gemma 4 12B | `gemma4:12b` | 7.6GB | 成功 | 全 GPU，预计约 7.7GB 显存 |
| Microsoft Phi-4 | `phi4` | 9.1GB | 成功 | 全 GPU，预计约 9.3GB 显存 |

从实测看，`llama3.1:8b` 和 `gemma4:12b` 最稳；`qwen3:14b`、`deepseek-r1:14b`、`phi4` 在 4K 上下文下也可以全 GPU 跑，但已经接近 12GB 显卡的舒适上限。`gpt-oss:20b` 是可用但偏勉强，适合短上下文和低并发测试，不太适合作为 3080 单卡上的日常首选。

另外，Ollama 官方的 `gpt-oss` 通用模型目前主要是 `20b` 和 `120b` 两档，`gpt-oss:20b` 已经是较小的通用版本。

## GSM8K 数学能力测评

为了比较数学推理能力，我用 `lm-evaluation-harness` 跑了 `gsm8k_cot`。这个任务是 GSM8K 的 8-shot chain-of-thought 生成式评测，主要看 `exact_match`。表里优先看 `flexible-extract`，因为它对答案格式更宽容；`strict-match` 则更依赖模型是否严格输出目标格式。

测试命令核心参数：

```bash
lm-eval \
  --model local-chat-completions \
  --model_args "model=<ollama_model>,base_url=http://127.0.0.1:11435/v1/chat/completions,num_concurrent=1,max_retries=2,timeout=600,tokenized_requests=False" \
  --tasks gsm8k_cot \
  --apply_chat_template \
  --gen_kwargs max_gen_toks=512,temperature=0.0
```

本次有效落盘结果如下：

| 模型 | 评测范围 | flexible-extract | strict-match | 耗时 | 备注 |
|------|----------|-----------------:|-------------:|------|------|
| `llama3.1:8b` | 全量 1319 题 | 80.44% | 58.98% | 约 41 分 55 秒 | 正式全量结果 |
| `llama3.1:8b` | 抽样 100 题 | 79.00% | 63.00% | 约 3 分 20 秒 | 与全量结果接近 |
| `gemma4:12b` | 抽样 100 题 | 13.00% | 13.00% | 约 16 分 24 秒 | 能跑，但生成很慢，很多样本打满 512 token |
| `qwen3:14b` | 抽样 100 题 | 50.00% | 7.00% | 约 11 分 55 秒 | 能跑，答案格式不太符合 strict 抽取 |
| `deepseek-r1:14b` | 抽样 100 题 | 34.00% | 0.00% | 约 13 分 21 秒 | 能跑，推理输出格式导致 strict 为 0 |
| `gpt-oss:20b` | 抽样 100 题 | 76.00% | 0.00% | 约 11 分 26 秒 | 能跑，显存约 10.3GB，格式导致 strict 为 0 |
| `phi4` | 抽样 100 题 | 91.00% | 68.00% | 约 3 分 42 秒 | 需把 Ollama 上下文降到 2048 后稳定跑完 |

这次可以确认几点：第一，`phi4` 在 100 题抽样里最高，速度也最快；第二，`llama3.1:8b` 在 3080 12GB 上跑 GSM8K 很稳，数学表现也不错；第三，`gpt-oss:20b` 的抽样分数接近 `llama3.1:8b`，但显存占用更高，更接近 3080 12GB 的上限；第四，`qwen3:14b`、`deepseek-r1:14b`、`gpt-oss:20b` 的 strict-match 明显偏低，主要是输出格式和 `gsm8k_cot` 的严格抽取规则不匹配，横向比较时更应该看 flexible-extract。`gemma4:12b` 虽然能稳定跑完抽样，但在这个配置下分数明显偏低，并且速度慢。

第一次跑长评测时，SSH tunnel / Ollama API 中途断开。后续改成用 Windows 自己创建 Ollama 进程，再只用 SSH 做端口转发，所有模型都能完成抽样评测。`phi4` 初次在默认 4096 上下文下触发过 Ollama `llama-server` 的 Windows 崩溃，错误码 `0xc0000005`；把 `OLLAMA_CONTEXT_LENGTH` 降到 `2048` 后，短请求、5 题烟测和 100 题抽样都能稳定完成。若要做所有模型全量 1319 题横评，建议继续使用这种启动方式，或者直接在 Windows 本机执行 `lm-evaluation-harness`，减少长时间端口转发的不确定性。

## 运行注意

- 3080 显存有限，建议优先选 Q4 量化版本。
- 10GB 版本比 12GB 版本更容易爆显存，必要时降低上下文长度。
- 上下文长度越大，KV Cache 占用越高；模型权重能放下，不代表长上下文也能放下。
- 20B 模型属于边缘可用，30B/32B 以上不建议作为 3080 单卡的日常选择。
- 如果只是日常问答和代码辅助，8B-14B 模型通常比硬跑 20B/30B 更均衡。
