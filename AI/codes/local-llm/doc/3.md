# 基础采样解码（Sampling Decoding）实现与测试总结

本文记录为 local-llm 增加**基础采样解码**（temperature / top-k / top-p / repetition penalty）的动机、实现方式与远端 CUDA 机器上的验证结果。

**结论先行**：采样解码实现正确——Qwen 用采样输出简洁正确并自然触发 EOS；采样能有效打破贪心（argmax）的重复死循环。DeepSeek-V2-Lite（含 chat 版）后段仍会退化为碎字 token，这是**模型本身能力弱**（2.4B 激活量、base/社区微调）导致，与采样器无关；同一套采样代码在 Qwen 上完全正常。默认 `temperature=0` 仍是贪心，向后兼容旧行为。

## 一、背景与动机

此前 local-llm 的解码是纯 **argmax 贪心**（`src/backend/cuda/ops/kernel.cu` 的 `launch_argmax`），没有任何采样或重复惩罚。表现为：

- Qwen3.5-4B-Base：能连贯生成，但作为 base 模型偏发散。
- DeepSeek-V2-Lite（base 与 chat 版）：首句常常正确（如 "The capital of France is → Paris."），但随即陷入 `the the the...` / `的的的的...` 的重复死循环。

排查已确认（见 [`smoke_result.txt`](./smoke_result.txt)）：重复退化是**贪心解码固有现象**，与模型权重、tokenizer、以及此前 TensorContainer/DType 重构均无关。base 与 chat 两个 GGUF 结构（张量名/shape/量化类型/超参/tokenizer 元数据）完全一致，仅权重数值不同。

因此正确的解法是加**采样解码**，而非替换权重文件。

## 二、实现

### 2.1 新增 host 端采样器

新增 [`src/llm/sampling/Sampler.h`](../src/llm/sampling/Sampler.h) / [`Sampler.cpp`](../src/llm/sampling/Sampler.cpp)。

配置结构：

```cpp
struct SamplingConfig {
    float temperature = 0.0f;        // <=0 -> greedy(argmax)
    int   top_k = 0;                 // <=0 -> disabled
    float top_p = 1.0f;              // >=1 或 <=0 -> disabled
    float repetition_penalty = 1.0f; // <=1 -> disabled
    uint64_t seed = 42;
};
```

采样流程（`Sampler::sample(float* logits, int vocab, const std::vector<int>& prev_tokens)`）：

1. **重复惩罚**：对上下文中已出现的 token 施加惩罚（HF 约定：正 logit `/penalty`、负 logit `*penalty`，都使其更不易被选中）。
2. **贪心短路**：`temperature <= 0` 时直接取 argmax，忽略 top-k/top-p，等价旧行为。
3. **温度缩放**：`logits *= 1/temperature`。
4. **top-k 截断**：`std::partial_sort` 取前 k 大（k<=0 或 >=vocab 时不截断）。
5. **softmax**：对截断后的候选做数值稳定 softmax（减最大值）。
6. **top-p（nucleus）截断**：按降序累加概率，保留累计到 `top_p` 的最小候选集，再重归一化。
7. **采样**：`std::discrete_distribution` 按概率采样，返回 token id。

### 2.2 为什么放在 host 端

logits 每步只有 `vocab` 个 float（Qwen ~151k、DeepSeek 102400），D2H 拷贝（约 0.4–0.6 MB）相对整条前向可忽略。放在 host：

- top-k/top-p/温度/重复惩罚逻辑清晰，无需新增 CUDA kernel；
- 天然可在无 CUDA 环境（如 macOS）编译与单元验证；
- 便于后续扩展（如 min-p、typical sampling）。

### 2.3 接入两条推理路径

计算出 logits 后不再走 device argmax，改为 `cudaMemcpy` 拷回 host 暂存（各 ForwardScratch 新增 `std::vector<float> h_logits`），调用 `sampler.sample(h_logits, vocab, session.h_outputs)`。`session.h_outputs` 为已生成 token 历史，用于重复惩罚（prefill 首 token 时为空，天然不惩罚）。

- Qwen：[`src/llm/qwen/model/LMHead.cpp`](../src/llm/qwen/model/LMHead.cpp)（`forward` 增加 `Sampler&` 与 `prev_tokens` 参数），由 [`QwenModel`](../src/llm/qwen/model/QwenModel.cpp) 持有 `Sampler sampler_`。
- DeepSeek：[`src/llm/deepseek/model/DeepseekModel.cpp`](../src/llm/deepseek/model/DeepseekModel.cpp)（`forward` 末尾拷回 host 采样），持有 `Sampler sampler_`。

### 2.4 CLI 参数与透传

[`src/utils/cli/Args.{h,cpp}`](../src/utils/cli/Args.h) 新增采样参数，一路透传 `Args -> create_model -> QwenModel/DeepseekModel`（见 [`ModelFactory`](../src/llm/ModelFactory.cpp)）：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--temperature` | 0（贪心） | >0 启用采样 |
| `--top-k` | 0（关闭） | 保留 logit 最大的 k 个候选 |
| `--top-p` | 1.0（关闭） | nucleus 累计概率阈值 |
| `--repetition-penalty` | 1.0（关闭） | 建议 1.1 左右 |
| `--seed` | 42 | 采样随机种子 |

**默认 `temperature=0` 即贪心，与旧行为完全一致，向后兼容。**

## 三、测试环境

- **硬件**：远端 RTX A4500（20GB），CUDA 12.4（`/usr/local/cuda`）
- **构建**：`cmake --build build -j`（Release，`-DCMAKE_CUDA_ARCHITECTURES=86`），`BUILD_EXIT=0`
- **模型**：
  - Qwen3.5-4B-Base（safetensors）
  - DeepSeek-V2-Lite.Q4_K_M.gguf（base）
  - DeepSeek-V2-Lite-Chat.Q4_K_M.gguf（chat）
- **prompt**：通过环境变量 `PROMPT` 传入
- **本机语法自检**：`c++ -std=c++20 -I src -fsyntax-only src/llm/sampling/Sampler.cpp`（及 `Args.cpp`）通过；CUDA TU 以远端实际编译为准。

## 四、运行命令

贪心（默认）：

```bash
PROMPT="法国的首都是" ./build/local_llm --model qwen --model-dir <Qwen 目录> --max-output-tokens 40
```

采样：

```bash
PROMPT="法国的首都是" ./build/local_llm --model qwen --model-dir <Qwen 目录> \
    --max-output-tokens 40 --temperature 0.8 --top-k 40 --top-p 0.9 --repetition-penalty 1.1 --seed 7
```

DeepSeek 只需把 `--model qwen --model-dir <目录>` 换成 `--model deepseek --model-dir <.gguf 路径>`。

## 五、结果对比

（`max_output_tokens ≈ 40–50`）

### Qwen3.5-4B-Base　`PROMPT="法国的首都是"`

- **GREEDY**：`哪个城市？\n\n嗯，用户问的是法国的首都是哪个城市……`（连贯长文，偏发散）
- **SAMPLING**（temp=0.8 top_k=40 top_p=0.9 rep=1.1 seed=7）：`什么？\n\n法国的首都是巴黎。` 后**自然触发 EOS 停止**

> 采样器工作正常：输出简洁正确，并能正常在句末停下。这是采样逻辑正确的关键证据。

### DeepSeek-V2-Lite base　`PROMPT="The capital of France is"`

- **GREEDY**：` Paris. The capital of the the the the ...`（首句正确后 `the` 死循环）
- **SAMPLING**（temp=0.8 top_p=0.95 rep=1.1）：` Paris. In the is an the capital of ...` 之后碎成单字 token（`i n a a r e o f ...`）

### DeepSeek-V2-Lite-Chat　`PROMPT="法国的首都是"`

- **GREEDY**：`法国的的的的的的。……不不他他我我……`（死循环/乱码）
- **SAMPLING**（temp=0.7 top_k=40 top_p=0.9 rep=1.3）：`那个这个位置，对中法大大。法国国首都是是吗？`（打破死循环，产出有变化的文本，但质量仍低）

## 六、结论

1. **采样器实现正确**：Qwen 用同一套采样代码输出简洁正确（"法国的首都是巴黎。" + 自然 EOS），证明 temperature / top-k / top-p / 重复惩罚逻辑无误。
2. **采样能打破贪心死循环**：base/chat 的 `the the` / `的的的` 循环在开启采样后消失。
3. **DeepSeek-V2-Lite（含 chat）后段仍碎成单字 token**，这是**模型本身能力弱**（2.4B 激活量、base/社区微调）导致，与采样器无关——同样的采样代码在 Qwen 上完全正常。
4. **过高的 `repetition_penalty`（如 1.3）会过度惩罚常见词、反而更快退化**，建议 1.1 左右。
5. **默认 `temperature=0` 仍是贪心，向后兼容旧行为**；需要更好文本时推荐：
   ```
   --temperature 0.7~0.8 --top-k 40 --top-p 0.9 --repetition-penalty 1.1
   ```

## 七、后续可选方向

- 增加 min-p / typical sampling 等采样策略。
- 重复惩罚纳入 prompt token（当前只惩罚已生成 token）；可选支持滑动窗口 penalty。
- 若追求更高质量对话，需换用能力更强的 Instruct 模型，而非仅调解码参数。
