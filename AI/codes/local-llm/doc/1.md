# 投影前统一转权重 dtype（gemm 激活精度对齐）

本文说明本次对 `.h` / `.cpp` 的一批修改的原因。改动集中在“喂给 `cublasGemmEx` 的激活精度”这一件事上，并顺带把这段逻辑封装成 gemm 层的公共 helper。

涉及文件：

- [`gemm.h`](../src/backend/cuda/ops/gemm.h) / [`gemm.cpp`](../src/backend/cuda/ops/gemm.cpp)：新增 `to_weight_lowp`
- [`SwiGLUMlp.cpp`](../src/llm/qwen/model/SwiGLUMlp.cpp)
- [`FullAttention.cpp`](../src/llm/qwen/model/FullAttention.cpp)
- [`LinearAttention.cpp`](../src/llm/qwen/model/LinearAttention.cpp)
- [`LMHead.cpp`](../src/llm/qwen/model/LMHead.cpp)

## 一、根因：cublasGemmEx 要求 A 与 B 同 dtype

`gemm_weight` 底层调用 `cublasGemmEx`。该 API 要求参与乘法的两个矩阵（权重 A、激活 B）使用**相同的数据类型**。

Qwen 的线性层权重以 **BF16** 存储（safetensors 原样），而前向过程中的激活是 **FP32**。改动前各 Module 直接把 FP32 激活以 `x_type=CUDA_R_32F` 传入 `gemm_weight`：

```cpp
// 改动前（错误）：BF16 权重 × FP32 激活
gemm_weight(pool_->handle, *gate, intermediate, hidden_size, d_in, CUDA_R_32F, rows, d_gate);
```

BF16 × FP32 的混合组合不被 `cublasGemmEx` 支持，运行时首个矩阵乘即抛出
`CUBLAS_STATUS_NOT_SUPPORTED (status=15)`（错误信息 “cublasGemmEx 投影失败”）。

参考项目 `llm-inference-cpp` 的做法一致：所有喂给 gemm 的激活都先转成权重 dtype 再相乘。

## 二、修复：投影前把激活转成权重 dtype

在每次 `gemm_weight` 之前，先把 FP32 激活转成权重的低精度类型（BF16/F16）写入一块临时 buffer，再以 `x_type = weight.type` 参与乘法：

```cpp
// 改动后：激活先转成权重 dtype，x_type 传权重 type
uint16_t *d_in_lowp = scratch.input_lowp_buffer.ensure(rows * hidden_size, "mlp in lowp");
to_weight_lowp(d_in, d_in_lowp, rows * hidden_size, *gate, nullptr);
gemm_weight(pool_->handle, *gate, intermediate, hidden_size, d_in_lowp, gate->type, rows, d_gate);
```

各 Module 需要转换的投影输入：

| Module | 转换点 |
| --- | --- |
| `SwiGLUMlp` | 输入激活（gate/up 共享，转一次）；`SiLU(gate)*up` 的 prod（down 投影输入） |
| `FullAttention` | 输入激活（q/k/v 共享，转一次）；attention 输出（o_proj 输入） |
| `LinearAttention` | 输入激活（qkv/z/b/a 共享，转一次）；gated 输出（out_proj 输入） |
| `LMHead` | 输入激活（复用 embed_tokens 权重做输出投影） |

配套地在 `QwenForwardScratch` 增加 `input_lowp_buffer` 作为 gemm 输入的通用低精度缓冲。
**共享同一输入的多次投影只转一次**（如 q/k/v 都来自同一 hidden），避免重复转换开销。

## 三、封装：gemm 层的 `to_weight_lowp`

转换本身是一句 kernel 调用 `launch_float_to_lowp`，但它需要一个映射：把权重的
`cudaDataType_t` 翻译成 kernel 约定的 `lowp_type`（`0=bf16, 1=f16`）。

这个映射属于 gemm/cuBLAS 层的概念，不应下沉进 kernel 层（kernel 只认识自己的 `lowp_type`，
不该依赖 `cudaDataType_t`，否则造成层次倒挂）。因此把它封装成 gemm 层的 helper：

```cpp
// gemm.h
void to_weight_lowp(const float *d_x, uint16_t *d_x_lowp, int n,
                    const CudaWeight &weight, void *stream);

// gemm.cpp
static int lowp_of(cudaDataType_t type) { return type == CUDA_R_16F ? 1 : 0; }
void to_weight_lowp(const float *d_x, uint16_t *d_x_lowp, int n,
                    const CudaWeight &weight, void *stream) {
    launch_float_to_lowp(d_x, d_x_lowp, n, lowp_of(weight.type), stream);
}
```

好处：

1. 消除了 4 个 Module 中重复的 `lowp_of(w->type)` + `launch_float_to_lowp(...)` 样板；
2. 调用点只需传 `CudaWeight`，不必自己处理 dtype → lowp_type 的映射；
3. `lowp_of` 的 cuBLAS dtype 知识收敛在 gemm 层内部（`gemm.cpp` 的文件内 `static` 函数），
   kernel 层保持纯粹。
