# Qwen3.5-4B 在 RTX 3080 上的加载和推理耗时

## 测试环境

这次是在 Windows 机器的 WSL2 环境中运行：

```text
host: 
WSL distro: Ubuntu-D
project: /home/zyl/llm-inference-python
GPU: RTX 3080
model: Qwen/Qwen3.5-4B
dtype: float16
device: cuda
cache-dir: /home/zyl/hf-cache
```

运行命令：

```bash
python main.py \
  --prompt "介绍一下 TCP 三次握手" \
  --device cuda \
  --dtype float16 \
  --max-new-tokens 64 \
  --greedy \
  --cache-dir /home/zyl/hf-cache
```

## 实测结果

原始输出中的关键耗时：

```text
开始加载 Qwen/Qwen3.5-4B ...
Loading weights: 100%|...| 723/723 [00:05<00:00, 126.10it/s]
模型加载完成，耗时 16.29s，device=cuda，dtype=torch.float16

开始推理...
推理完成，耗时 4.64s，max_new_tokens=64
```

结果汇总：

| 阶段 | 耗时 | 说明 |
|------|------|------|
| 权重文件读取进度条 | 约 5s | safetensors 权重读取进度显示 |
| 模型整体加载完成 | 16.29s | 包含配置、tokenizer、权重读取、CPU/RAM 到 GPU VRAM 拷贝等 |
| 推理 | 4.64s | 生成 64 个 token，greedy decoding |

这次输出开头还出现了 Hugging Face 未登录提示：

```text
Warning: You are sending unauthenticated requests to the HF Hub.
Please set a HF_TOKEN to enable higher rate limits and faster downloads.
```

不过本次使用了本地缓存目录 `/home/zyl/hf-cache`，权重进度条也已经在本地加载阶段完成。这个提示主要影响从 Hugging Face Hub 下载/拉取时的限速和稳定性，不一定是这次 16.29s 加载耗时的主要原因。

## 初步判断

本次耗时可以拆成两段看：

```text
模型加载: 16.29s
推理生成: 4.64s / 64 tokens
```

加载阶段明显比权重读取进度条本身更长，说明除了文件读取，还包含模型对象构造、张量反序列化、dtype/device 转换、以及 CPU/RAM 到 GPU VRAM 的拷贝。即使用了类似 mmap 的文件映射，也不能省掉最终把权重放进 GPU 显存这一步。

推理阶段 64 token 用 4.64s，约等于：

```text
64 / 4.64 ~= 13.8 tokens/s
```

如果后续继续优化，加载阶段可以重点看：

- 权重是否已经完全在 WSL2 内的 Linux 文件系统里，而不是跨 `/mnt/c` 或 Windows 文件系统访问。
- 是否使用 safetensors 的 mmap/lazy loading 路径。
- 是否避免不必要的 CPU dtype 转换和重复 `.to("cuda")`。
- 是否可以预热进程，避免每次请求都重新加载模型。

推理阶段可以重点确认：

- 是否真正启用了 KV cache。
- 是否走到 flash-linear-attention / Triton fast path。
- 首次运行是否包含 Triton JIT 编译时间。
- batch size、上下文长度和生成长度是否符合预期。
