# 模型加载耗时优化：思路与效果

## 背景

原始的 `load_model` 把权重加载到内存的流程较慢，尤其在 8B 模型上。目标是在不改变模型结构和推理结果的前提下，显著降低「把模型加载到内存」的耗时。

## 优化前的做法与瓶颈

优化前 `load_model` 的核心步骤：

1. `SimpleLLM(cfg)`：在真实设备上构造模型，会为全部参数**分配内存并随机初始化**。
2. `load_state_dict(model_dir)`：用 `safetensors.torch.load_file` 把所有权重分片**全量实体化**进一个 dict。
3. `map_llama_keys`：再建一个新 dict 做 key 映射。
4. `model.load_state_dict(mapped)`：把权重**再拷贝一份**进模型参数。
5. `model.to(device, dtype)`：dtype 不一致时再拷一份做类型转换。

三个主要瓶颈：

- **随机初始化被浪费**：第 1 步给 8B 全部参数分配几十 GB 内存并写入随机数，紧接着就被真实权重覆盖，纯属浪费。
- **多份内存拷贝**：权重经历「文件 → dict → mapped dict → 模型参数」，存在 2~3 份实体化拷贝，外加反序列化开销。
- **内存压力导致抖动**：反复分配/释放几十 GB 内存，受系统内存回收影响，耗时波动极大。

## 优化后的做法

1. **meta 设备构造骨架**：用 `with torch.device("meta")` 构造 `SimpleLLM(cfg)`，只建出层结构与参数的 shape/dtype，**不分配真实内存、不做随机初始化**，瞬间完成。
2. **mmap 懒加载 + 直接映射**：用 `safetensors.safe_open(..., framework="pt", device=...)` 对权重文件做内存映射（mmap），逐张量 `get_tensor` 直接映射到目标设备，无反序列化、无多余 dict 拷贝。`.bin` 走 `torch.load(mmap=True)`。
3. **逐张量原地赋值**：`_set_module_tensor` 把每个真实张量替换掉模型里的 meta 占位（`nn.Parameter` / buffer），避免整份 `load_state_dict` 的额外拷贝。
4. **按需 dtype 转换**：仅当张量 dtype 与目标不一致时才 `.to(dtype)`，一致时零转换。
5. **重建非持久 buffer**：RoPE 的 `cos_cached` / `sin_cached` 是 `persistent=False` 的 buffer，不在权重文件里，meta 构造后为空，加载后通过 `_rebuild_rope_cache` 在目标设备上重新计算，保证推理正确。

## 关键代码位置

- `tool/model_loader.py`：`load_model`（meta 构造 + 校验 + 重建 RoPE 缓存）、`_rebuild_rope_cache`
- `tool/weights.py`：`load_into_model`（mmap 懒加载主流程）、`_set_module_tensor`（替换 meta 占位）

## 效果（CPU，DeepSeek-R1-Distill-Llama-8B，fp32）

在同一进程内先预热磁盘页缓存（排除下载与冷缓存干扰），优化前后各连测 3 次，仅测量「加载到内存」耗时：

| 方案 | best | avg |
|------|------|------|
| 优化前（随机初始化 + 全量 load_file + load_state_dict + .to） | 50.78s | 86.46s |
| 优化后（meta 骨架 + safe_open mmap 懒加载） | 2.87s | 2.90s |

- 按最优值：**提速约 17.7 倍**，单次节省约 47.9s
- 按平均值：**提速约 29.8 倍**，单次节省约 83.6s
- 优化后耗时非常稳定（2.87 / 2.88 / 2.94s）；优化前波动大（50~123s），因为反复分配/释放几十 GB 内存受系统内存压力影响。

## 注意事项

- **meta 设备只有形状没有数据**：任何在 `__init__` 里现算、又不进权重文件的张量（如 RoPE sin/cos 缓存）必须在加载后手动重建，否则推理会因空张量报错。
- 本优化只改加载路径，不改变模型结构与推理数值结果。
