# llm-train-cpp（BLAS 优化后）VS llm-train-python 对比（v2）

本文记录 C++ 版引入 **Accelerate BLAS（`cblas_dgemm`）** 优化 matmul 之后，与 PyTorch 参考实现的性能与结果对比。承接 [v1.md](./v1.md) 的对齐结论，本轮聚焦「优化后重新实测」。

- `AI/codes/llm-train-cpp`：C++17 手写实现，matmul 前/反向改用 Accelerate `cblas_dgemm`（`LLM_CPP_USE_BLAS`，macOS 自动启用）。
- `AI/codes/llm-train-python`：PyTorch 2.8.0 参考实现，`torch.cuda.is_available() == False`（落 CPU）。

测试环境：Apple M3 Pro（无 NVIDIA GPU，两边均 CPU 运行）。两档配置与 v1 一致：

| 配置 | vocab | ctx | emb | heads | layers | epochs |
|------|-------|-----|-----|-------|--------|--------|
| normal | 50257 | 256 | 768 | 12 | 12 | 10 |
| small  | 1360  | 64  | 128 | 4  | 3  | 30 |

共同超参：`batch=2`、`stride=ctx`、不 shuffle、`drop_last=True`、种子 123，AdamW `lr=4e-4, weight_decay=0.1`。

运行方式：C++ `train_gpt <backend> [small|normal]`；Python `python main.py [small|normal]`。

---

## 1. 性能对比

### 1.1 small 档（1080 step，全程实测）

| 实现 | 总耗时 | 单步耗时 | 相对 |
|------|-------|---------|------|
| **C++ Release + BLAS (CPU)** | 49.0 s | **~45 ms/step** | 1.0x |
| **Python (PyTorch CPU)** | 17.1 s | **~15.8 ms/step** | ~2.9x 更快 |

- C++ 引入 BLAS 后，small 档相比 v1 记录的朴素 Release（~2.3 s/step）快约 **50x**。
- 与 PyTorch CPU 的差距从此前的两个数量级收窄到 **~3x**，进入同一量级。

### 1.2 normal 档（V=50257，12 层，单步估算）

normal 单步很重，取「跑到不同 step 的 wall time 两点差分」以扣除固定的模型/数据初始化开销：

| 实现 | 单步耗时（估算） | 测量方式 |
|------|-----------------|---------|
| **C++ Release + BLAS (CPU)** | **~3.0 s/step** | (81.3s@11步 − 66.0s@6步) / 5 步 |
| **Python (PyTorch CPU)** | **~0.6–0.8 s/step** | 21.3s 跑到 step 15（含 import ~3s + 每 5 步 val 评估） |

差距约 **4–5x**（Python 更快），比 small 档略大。

> 注：normal 数字为量级估算而非精确值——单步很重、且 Python 每 5 步含一次 val 评估（额外 forward）、并用了多核。结论「同量级、Python 快约 4–5x」是稳健的。

### 1.3 优化解读

- **BLAS 命中的是矩阵乘**：把手写三重循环 matmul（前向 `C=A·B`、反向 `dA=dC·Bᵀ`、`dB=Aᵀ·dC`）替换为 `cblas_dgemm`（多线程 + NEON 向量化 + 缓存分块）。small 档矩阵乘占比高，收益最直接。
- **normal 差距反而更大的原因**：BLAS 让矩阵乘近乎免费后，瓶颈**转移到 V=50257 输出层的非矩阵乘算子**——cross_entropy / softmax 的 `exp`、全词表 elementwise 仍是朴素 double 循环，词表越大这块短板越明显。
- **剩余 3–5x 差距根因**：C++ 底层用 double（PyTorch 用 float，SIMD 吞吐翻倍）、逐算子多次派发无融合、非矩阵乘算子未向量化。属教学框架设计取舍，非 bug。

## 2. 结果 diff 对比

BLAS 只改变算子实现，不改变数值语义；loss 逐位与优化前一致，与 Python 同分布对齐。

### 2.1 small 档逐 step loss

| step | C++ + BLAS (CPU) | Python (CPU) | 差异 |
|------|------------------|--------------|------|
| 0    | 7.33287 | 7.33657 | 0.004 |
| 1    | 7.44476 | 7.31608 | 0.129 |
| 2    | 7.35412 | 7.40305 | 0.049 |
| 3    | 7.36266 | 7.32775 | 0.035 |
| 1079（末）| **0.08854** | **0.08396** | 0.005 |

- 起始 loss ≈ `ln(1360) ≈ 7.22`，符合随机初始化的交叉熵理论值。
- 起点、终点高度一致（差 <0.006）；中间个别 step 差异略大（如 step 1 = 0.129）来自逐 batch 顺序 + float/double 精度的正常抖动，整体收敛轨迹一致。
- **C++ BLAS 版起点 loss 7.33287 与 v1 优化前逐位相同** —— 印证 BLAS 替换未改变数值结果。

### 2.2 normal 档逐 step loss（收敛趋势）

| step | C++ + BLAS (CPU) | Python (CPU) |
|------|------------------|--------------|
| 0  | 11.02 | 9.90 |
| 5  | 8.68  | 7.92 |
| 10 | 6.81  | 6.85 |
| 15 | —     | 6.00 |

- 两边同量级、同下降趋势收敛，到 step 10 已收敛到相近水平（6.81 vs 6.85）。
- 起点差异（11.0 vs 9.9）来自两边随机初始化虽同种子但 RNG 实现不同，属预期内。

---

## 3. 结论

- **性能：BLAS 后追平量级。** small 档 C++ 从 ~2.3 s/step 降到 ~45 ms/step（约 50x），与 PyTorch CPU 的 ~15.8 ms 进入同一量级（~3x）；normal 档 ~3.0 s/step vs Python ~0.6–0.8 s/step（~4–5x）。
- **正确性：不变。** BLAS 只换算子实现，loss 起点逐位不变、收敛轨迹与 Python 一致；71 项单测全过。
- **下一步可优化点**：normal 档瓶颈已转移到词表规模的 softmax/cross_entropy 的 `exp` 与 elementwise，可考虑向量化或改 float 存储进一步缩小差距。
