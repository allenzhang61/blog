# 压测并调优 vLLM + Qwen3.5-9B

## 环境

| 项目 | 配置 |
|------|------|
| 实例 | vast.ai RTX 4090（24GB） |
| vLLM | 0.23.0 |
| 模型 | Qwen/Qwen3.5-9B（BF16，17.65GB） |
| CUDA | 13.2 / Driver 595.58 |

---

## 启动 API 服务

```bash
nohup python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen3.5-9B \
  --download-dir /workspace/models \
  --max-model-len 8192 \
  --max-num-seqs 32 \
  --gpu-memory-utilization 0.90 \
  --compilation-config '{"cudagraph_capture_sizes":[1,2,4,8,16,32]}' \
  --host 127.0.0.1 --port 18000 \
  > /tmp/vllm_server.log 2>&1 &
```

> 首次启动约 3 分钟（torch.compile 编译），第二次起命中缓存约 2 分钟。

健康检查：

```bash
curl http://127.0.0.1:18000/health
```

---

## 压测

使用 vLLM 内置工具 `vllm bench serve`，模拟随机请求（input 512 tokens，output 128 tokens），分三档并发压测：

```bash
vllm bench serve \
  --model Qwen/Qwen3.5-9B \
  --host 127.0.0.1 --port 18000 \
  --dataset-name random \
  --random-input-len 512 --random-output-len 128 \
  --num-prompts 50 --request-rate <RATE>
```

### 压测结果

| 指标 | rate=1 | rate=5 | rate=10 |
|------|--------|--------|---------|
| 成功请求数 | 50 | 50 | 50 |
| 实际吞吐（req/s） | 0.95 | 2.56 | **3.11** |
| 输出吞吐（tok/s） | 122 | 327 | **398** |
| 总吞吐（tok/s，含输入） | 609 | 1637 | **1989** |
| Mean TTFT（ms） | 583 | 2149 | 3389 |
| Median TTFT（ms） | **162** | 2448 | 3699 |
| P99 TTFT（ms） | 1958 | 6478 | 7351 |
| Mean TPOT（ms） | 25 | 41 | 36 |
| P99 TPOT（ms） | 46 | 55 | 63 |

### 结论

```
吞吐峰值：~398 tok/s（rate=10）
低延迟区间：rate ≤ 1，Median TTFT 162ms
饱和点：rate=5~10 之间，吞吐增幅 21%，TTFT 翻 1.5x
```

rate=10 时 GPU 已接近饱和，继续加压只会堆积队列，TTFT 线性恶化。实际生产中，吞吐与延迟需要根据 SLA 做取舍。

## 调优方向

### 1. 增大并发（提升吞吐）

```bash
--max-num-seqs 8   # 保守
--max-num-seqs 32  # 本次测试配置
--max-num-seqs 64  # 激进，需要有足够 KV Cache 空间
```

每次翻倍测一轮，直到 P99 TTFT 超出 SLA 为止。

---

### 2. Chunked Prefill（降低 TTFT）

将长 prompt 的 prefill 拆成小块与 decode 交织执行，减少首 token 等待：

```bash
--enable-chunked-prefill \
--max-num-batched-tokens 2048
```

适合 input 较长（>512 tokens）的场景，可将 Mean TTFT 降低 30~50%。

---

### 3. Prefix Caching（提升相同前缀场景的吞吐）

对多轮对话、相同 system prompt 的请求，自动复用 KV Cache：

```bash
--enable-prefix-caching
```

相同 system prompt 命中率高时，吞吐提升 1.5~2x，TTFT 大幅下降。本次测试中关闭了此项（随机请求，无前缀复用价值）。

---

### 4. FP8 量化（省显存，提升吞吐）

模型从 BF16（17.65GB）压缩到 FP8（~9GB），释放大量显存给 KV Cache：

```bash
--quantization fp8
```

| 配置 | 模型显存 | 可用 KV Cache | 预期吞吐提升 |
|------|----------|---------------|------------|
| BF16（当前） | 17.65 GB | 1.41 GB | 基准 |
| FP8 | ~9 GB | ~10 GB | ~2x |

Qwen3.5-9B 原生支持 FP8，无需额外校准。

---

### 5. 缩小 max_model_len（省 KV Cache）

KV Cache 大小与 `max_model_len` 成正比。够用的前提下尽量小：

```bash
--max-model-len 4096   # 比 8192 节省约一半 KV Cache
```

---

### 6. 调优总览

| 目标 | 推荐参数 |
|------|---------|
| 最大吞吐 | `max-num-seqs=64` + `fp8` + `enable-prefix-caching` |
| 最低延迟 | `max-num-seqs=8` + `enable-chunked-prefill` + `max-num-batched-tokens=1024` |
| 省显存（24GB 卡） | `fp8` + `max-model-len=4096` |
| 多轮对话 | `enable-prefix-caching` + `max-model-len=32000` |
