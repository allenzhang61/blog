## 按使用场景选择

### 本地开发 / 个人部署

优先看：

- **Ollama**：最省心，模型下载、运行、API 服务都比较顺滑。
- **llama.cpp**：更底层、更轻量，GGUF 生态强，适合 CPU、Mac、边缘设备。
- **LocalAI**：想用 OpenAI API 兼容接口跑多类本地模型时比较方便。

### 生产级 LLM API

优先看：

- **vLLM**：当前最主流的高吞吐 LLM serving 选择之一，OpenAI-compatible API，生态成熟。
- **SGLang**：适合复杂推理、结构化输出、agent workflow，以及对吞吐/延迟要求高的服务。
- **TGI**：Hugging Face 生态友好，部署 Transformer 模型比较直接。
- **LMDeploy**：中文模型生态里常见，适合 InternLM、Qwen 等模型部署。

### NVIDIA GPU 极致性能

优先看：

- **TensorRT-LLM**：偏底层优化，性能强，但构建和调参复杂度更高。
- **Triton Inference Server**：更像生产推理服务器底座，可托管 TensorRT、PyTorch、ONNX、Python backend 等。

### 复杂服务编排 / 多模型平台

优先看：

- **Ray Serve**：适合多模型、多步骤 pipeline、动态扩缩容、复杂业务逻辑。
- **KServe**：适合 Kubernetes 上做标准化模型服务和企业 MLOps。
- **BentoML**：适合把 Python 模型、LLM app、队列任务、pipeline 封装成服务。

## 一个简单结论

如果只考虑 LLM 自托管，常见选择可以简化成：

```text
本地最快上手：Ollama
本地/边缘/CPU：llama.cpp
生产高吞吐：vLLM
复杂推理工作流：SGLang
Hugging Face 生态：TGI
NVIDIA 极致性能：TensorRT-LLM + Triton
多模型平台/编排：Ray Serve / KServe / BentoML
```

单看 GitHub 热度，Ollama、llama.cpp、vLLM 排在前面；但如果限定在“生产级 LLM API server”，vLLM、SGLang、TGI、TensorRT-LLM、Triton 更值得重点比较。
