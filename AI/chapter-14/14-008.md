# vllm parallel 介绍

vLLM 里的 `parallel_config` 是用来描述“模型和请求如何被拆到多个进程、多个 GPU、多个节点上运行”的配置。

它不是只管一种并行方式，而是把多种架构放在同一个配置对象里统一管理，例如：

- 单机单卡
- 单机多卡
- 多机多卡
- 多副本服务
- MoE 专家模型的专家拆分
- 长上下文场景下的上下文拆分

对应源码位置：

```text
vllm/engine/arg_utils.py
  -> create_engine_config()
  -> parallel_config = ParallelConfig(...)

vllm/config/parallel.py
  -> class ParallelConfig
```

## 1. 单机单卡

这是最简单的模式。

```text
一个模型
一个 worker
一张 GPU 或 CPU
```

默认配置基本就是这个架构：

```python
tensor_parallel_size = 1
pipeline_parallel_size = 1
data_parallel_size = 1
```

如果在本地 Mac CPU 上跑 `examples/basic/offline_inference/basic.py`，理解成这个模式就可以。

## 2. 张量并行

张量并行的意思是：把模型某一层里的大矩阵计算拆到多张 GPU 上。

比如一个线性层权重很大，单卡放不下，或者单卡算得太慢，就可以切成几份：

```text
同一层模型权重
  -> GPU 0 负责一部分
  -> GPU 1 负责另一部分
```

对应参数：

```python
tensor_parallel_size = 2
```

直观理解：

```text
一个请求
同一层计算
多张 GPU 一起算
```

适合场景：

- 模型太大，单张 GPU 放不下
- 想提升单个请求的计算吞吐
- 常见于大模型推理部署

## 3. 流水线并行

流水线并行的意思是：把模型按层切开，不同 GPU 负责不同层。

例如：

```text
GPU 0: 第 1 层到第 20 层
GPU 1: 第 21 层到第 40 层
```

对应参数：

```python
pipeline_parallel_size = 2
```

直观理解：

```text
一个请求
模型不同层
分给不同 GPU 接力执行
```

适合场景：

- 模型层数很多
- 单卡放不下完整模型
- 多机多卡部署时，需要按层跨设备切分

## 4. 数据并行

数据并行的意思是：复制多份完整的 vLLM engine，每份处理不同请求。

例如：

```text
请求 A -> engine 0
请求 B -> engine 1
请求 C -> engine 2
```

对应参数：

```python
data_parallel_size = 4
```

直观理解：

```text
不是把一个请求拆开
而是把不同请求分给不同副本
```

适合场景：

- 在线服务
- 请求并发高
- 想提升整体吞吐

数据并行还会涉及这些参数：

```python
data_parallel_rank
data_parallel_size_local
data_parallel_backend
data_parallel_external_lb
data_parallel_hybrid_lb
```

它们主要用来描述：

- 当前副本编号是多少
- 本机有多少个数据并行副本
- 使用 multiprocessing 还是 Ray 管理进程
- 请求负载均衡由 vLLM 做，还是由外部网关做

## 5. 外部负载均衡和混合负载均衡

数据并行服务时，请求需要被分发到不同 engine。

vLLM 支持两类服务架构。

### 外部负载均衡

```python
data_parallel_external_lb = True
```

意思是：vLLM 不负责全局请求分发，而是交给外部系统。

例如：

```text
Kubernetes Service / Nginx / API 网关
  -> vLLM 副本 0
  -> vLLM 副本 1
  -> vLLM 副本 2
```

这种方式常见于生产部署。

### 混合负载均衡

```python
data_parallel_hybrid_lb = True
```

意思是：

```text
节点内部：vLLM 自己分发请求
节点之间：外部负载均衡分发请求
```

适合多节点部署时做折中。

## 6. 专家并行

专家并行主要用于 MoE 模型。

MoE 是 mixture of experts，也就是“专家混合模型”。这类模型里有很多 expert，不是每次都跑全部 expert，而是根据输入路由到其中一部分 expert。

专家并行的意思是：把不同 expert 放到不同 GPU 上。

例如：

```text
GPU 0: expert 0, expert 1
GPU 1: expert 2, expert 3
```

对应参数：

```python
enable_expert_parallel = True
```

专家放置策略：

```python
expert_placement_strategy = "linear"
expert_placement_strategy = "round_robin"
```

`linear` 是连续放置：

```text
GPU 0: expert 0, expert 1
GPU 1: expert 2, expert 3
```

`round_robin` 是轮询放置：

```text
GPU 0: expert 0, expert 2
GPU 1: expert 1, expert 3
```

适合场景：

- Mixtral
- DeepSeek
- 其他 MoE 模型

## 7. 专家负载均衡

MoE 模型有一个问题：有些 expert 可能经常被选中，有些 expert 很少被选中。

这样会导致：

```text
某些 GPU 很忙
某些 GPU 很闲
```

专家负载均衡就是为了解决这个问题。

对应参数：

```python
enable_eplb = True
eplb_config = ...
```

注意：

- 必须开启专家并行
- 当前主要支持 CUDA / ROCm 这类 GPU 平台

## 8. 上下文并行

上下文并行用于长上下文场景。

vLLM 里有两个相关参数：

```python
prefill_context_parallel_size
decode_context_parallel_size
```

可以这样理解：

```text
prefill 阶段：处理 prompt
decode 阶段：逐个生成新 token
```

所以：

- `prefill_context_parallel_size`：处理长 prompt 时的上下文并行数
- `decode_context_parallel_size`：生成 token 时的上下文并行数

它们主要解决长上下文 attention 计算和缓存压力。

## 9. 分布式执行后端

`parallel_config` 还会配置 worker 怎么启动。

对应参数：

```python
distributed_executor_backend
```

常见取值：

```python
"mp"
"ray"
"uni"
"external_launcher"
```

含义：

| 后端 | 含义 |
| --- | --- |
| `mp` | 使用 Python multiprocessing 启动 worker |
| `ray` | 使用 Ray 集群管理 worker |
| `uni` | 单 worker 模式 |
| `external_launcher` | worker 由外部系统启动 |

一般理解：

```text
单机多卡：常见是 mp
多机集群：可以用 ray 或 mp
TPU 平台：源码注释里说只支持 Ray
外部托管进程：external_launcher
```

## 10. 几种组合架构

实际部署时，这些并行方式可以组合。

### 单机多卡大模型

```python
tensor_parallel_size = 4
pipeline_parallel_size = 1
data_parallel_size = 1
```

含义：

```text
一个模型被切到 4 张 GPU 上
主要解决模型太大或单请求吞吐问题
```

### 多副本在线服务

```python
tensor_parallel_size = 1
pipeline_parallel_size = 1
data_parallel_size = 4
```

含义：

```text
4 份完整 engine
不同请求分给不同 engine
主要提升并发能力
```

### 大模型多卡加多副本

```python
tensor_parallel_size = 4
data_parallel_size = 2
```

含义：

```text
每个模型副本用 4 张 GPU
一共有 2 个模型副本
总共需要 8 张 GPU
```

### MoE 专家模型

```python
enable_expert_parallel = True
data_parallel_size = 2
tensor_parallel_size = 2
```

含义：

```text
普通层可以做张量并行
专家层可以做专家并行
多个副本处理不同请求
```

## 11. 学习顺序建议

建议按这个顺序理解：

1. 单机单卡
2. 张量并行
3. 数据并行
4. 流水线并行
5. 多机部署
6. MoE 专家并行
7. 上下文并行

一句话总结：

```text
张量并行：一个请求的一层，拆给多张 GPU 算
流水线并行：一个请求的不同层，拆给多张 GPU 接力算
数据并行：多个完整副本，分别处理不同请求
专家并行：MoE 模型的不同 expert，拆给不同 GPU
上下文并行：长上下文 attention，按上下文维度拆
```
