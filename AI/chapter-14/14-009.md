## 3. C++ 扩展调用关系图

vLLM 的 C++ 调用通常不是 Python 直接 `ctypes` 调 C++ 类，而是走
PyTorch extension 机制：

```text
Python
  -> torch.ops._C.xxx(...)
  -> C++ TORCH_LIBRARY 注册表
  -> CPU / CUDA / ROCm 具体实现函数
```

把 Python 和 C++ 放在同一张图里看，会更清楚：

这张图里有三种关系：

- 蓝色：Python 代码，负责导入、包装参数、调用 `torch.ops._C.xxx(...)`。
- 黄色：PyTorch extension 分发层，负责把 `_C` 动态库加载进来，并根据 op 名称
  找到 C++ 注册函数。
- 绿色：C++ / CUDA / ROCm 实现层，负责真正执行 CPU kernel、GPU kernel、
  oneDNN GEMM、共享内存通信等底层逻辑。

如果只看“涉及到的类/结构”，核心是下面这些：

```mermaid
classDiagram
    direction LR

    class CustomOpsPy {
      +rms_norm()
      +rotary_embedding()
      +onednn_mm()
      +cpu_fused_moe()

    class TorchOpsC {
      +torch.ops._C.xxx()
    }

    class CpuTorchBindings {
      +TORCH_LIBRARY_EXPAND(_C, ops)
      +ops.def()
      +ops.impl()
    }

    class RegistrationH {
      +REGISTER_EXTENSION(_C)
      +TORCH_LIBRARY_EXPAND()
      +TORCH_LIBRARY_IMPL_EXPAND()
    }

    class CPUDNNLGEMMHandler {
      +handler_tensor
      +__del__()
    }

    class DNNLMatMulPrimitiveHandler {
      <<cpp>>
      +prepack_weight()
      +set_runtime_memory_ptr()
    }

    class W8A8MatMulPrimitiveHandler {
      <<cpp>>
      +execute()
    }

    class MatMulPrimitiveHandler {
      <<cpp>>
      +execute()
    }

    class DNNLPrimitiveCache {
      <<cpp template>>
    }

    class ThreadSHMContext {
      <<cpp struct>>
      +set_context()
      +set_stamp_buffer_idx()
    }

    class SHMManager {
      <<cpp>>
      +allreduce()
      +gather()
      +all_gather()
    }

    class CustomAllreduce {
      <<cuda cpp>>
      +open_ipc_handle()
      +get_graph_buffer_ipc_meta()
    }

    CustomOpsPy --> TorchOpsC : 调用
    TorchOpsC --> CpuTorchBindings : 查注册表
    CpuTorchBindings --> RegistrationH : 依赖宏
    CustomOpsPy --> CPUDNNLGEMMHandler : Python 侧持有 handler
    CPUDNNLGEMMHandler --> DNNLMatMulPrimitiveHandler : C++ 指针封装为 int64 tensor
    DNNLMatMulPrimitiveHandler <|-- W8A8MatMulPrimitiveHandler
    DNNLMatMulPrimitiveHandler <|-- MatMulPrimitiveHandler
    W8A8MatMulPrimitiveHandler --> DNNLPrimitiveCache : 缓存 oneDNN primitive
    MatMulPrimitiveHandler --> DNNLPrimitiveCache : 缓存 oneDNN primitive
    CpuTorchBindings --> ThreadSHMContext : 注册共享内存通信函数
    CpuTorchBindings --> SHMManager : 注册共享内存通信函数
    TorchOpsC --> CustomAllreduce : GPU all-reduce 路径
```

这里要注意两点：

- `torch.ops._C.xxx` 里的 `_C` 是 PyTorch 自定义算子 namespace，不是一个普通
  Python 类。
- C++ 侧很多地方是函数和模板结构，不一定是面向对象的“类调用”。比如
  `rms_norm`、`rotary_embedding`、`cpu_fused_moe` 主要是注册到
  `torch.ops._C` 的 C++ 函数。

## 4. 读图顺序

如果只看 `basic.py` 离线推理，可以按这个顺序读：

```text
basic.py
  -> LLM
  -> EngineArgs
  -> VllmConfig
  -> LLMEngine
  -> EngineCoreClient
  -> EngineCore
  -> Scheduler
  -> Executor
  -> Worker
  -> ModelRunner
```

这条链路里最容易混淆的是 `LLMEngine` 和 `EngineCore`：

- `LLMEngine` 更靠近用户 API，负责接收请求、处理输入输出、维护请求状态。
- `EngineCore` 更靠近执行循环，负责调度、KV cache、调用 executor 执行模型。
- `EngineCoreClient` 是中间层：同进程时直接调用 `EngineCore`，多进程时通过
  ZMQ 和后台 `EngineCore` 通信。
