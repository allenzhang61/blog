# QKV 通俗理解

在自注意力机制里，每个 token 的原始 embedding 会被线性变换成三个向量：

```text
Q = Query
K = Key
V = Value
```

这三个名字一开始很抽象，但它们其实是在把同一个 token 拆成三个不同角色：

```text
Q：我现在想找什么信息？
K：我有什么特征，别人怎么判断我是否相关？
V：如果别人关注我，我实际贡献什么内容？
```

## 1. 一个图书馆例子

可以把注意力机制想象成在图书馆找资料。

假设你想查：

```text
RNN 和注意力机制有什么关系？
```

那么：

- `Q` 像你的检索需求：我想找什么？
- `K` 像每本书的索引标签：这本书适合被什么问题找到？
- `V` 像书里的正文内容：如果选中了这本书，它能提供什么信息？

查资料时，你不会一开始就通读所有书的正文，而是先用你的需求去匹配每本书的索引标签。

在注意力里也是这样：

```text
先用 Q 和 K 算相关性
再根据相关性决定看哪些 V
最后把 V 加权汇总成新的表示
```

## 2. 为什么不是一个向量，而是 Q、K、V 三个向量

一个 token 在注意力机制里至少有三种角色：

```text
作为提问者：我想找什么？        -> Q
作为被匹配者：我适合被谁找到？  -> K
作为信息提供者：我提供什么？    -> V
```

如果只用一个向量，那它就要同时承担这三件事：

```text
既要表达“我要找什么”
又要表达“别人怎么找到我”
还要表达“我提供什么内容”
```

这会限制模型的表达能力。

拆成 Q/K/V 后，模型可以分别学习这三种表示：

```text
同一个 token
-> 通过 W_q 得到 Query
-> 通过 W_k 得到 Key
-> 通过 W_v 得到 Value
```

公式是：

$$
Q = XW_q
$$

$$
K = XW_k
$$

$$
V = XW_v
$$

其中 `X` 是输入 token embedding 矩阵，`W_q`、`W_k`、`W_v` 是可训练参数。

## 3. Q 和 K 为什么要相乘

如果你能理解“相关系数”，那可以把 `QK^T` 理解成一种“相关性打分”。

对于当前 token，它的 Query 会和所有 token 的 Key 做匹配：

```text
当前 token 的 Q · 第 1 个 token 的 K
当前 token 的 Q · 第 2 个 token 的 K
当前 token 的 Q · 第 3 个 token 的 K
...
```

点积越大，说明越相关。

例如句子：

```text
The animal didn't cross the street because it was tired.
```

当模型处理 `it` 时：

- `it` 的 Q 可能在问：“我指代谁？”
- `animal` 的 K 可能表示：“我是一个可被代词指代的名词。”
- 所以 `it` 的 Q 和 `animal` 的 K 匹配分数会比较高。

矩阵形式就是：

$$
QK^T
$$

假设有 4 个 token，每个 Q/K 都是 `d` 维：

```text
Q: 4 x d
K: 4 x d
K^T: d x 4
```

那么：

```text
QK^T: 4 x 4
```

这个 `4 x 4` 矩阵表示：

```text
每个 token 对所有 token 的注意力打分
```

也就是说，第 `i` 行表示：

```text
第 i 个 token 想从其它 token 那里取信息时，分别有多相关。
```

## 4. 为什么要除以 sqrt(d_k)

实际公式不是直接 `QK^T`，而是：

$$
\frac{QK^T}{\sqrt{d_k}}
$$

其中 `d_k` 是 Key 向量的维度。

原因是：向量维度越大，点积的数值通常越大。点积分数太大时，经过 softmax 后会变得特别尖锐：

```text
[20, 1, 0] -> softmax -> 几乎 [1, 0, 0]
```

这样梯度会变小，训练不稳定。

除以 `sqrt(d_k)` 是为了把分数缩放到更合适的范围，让 softmax 不要过早变得极端。

所以：

```text
QK^T：算相关性
/ sqrt(d_k)：控制分数尺度
softmax：变成注意力权重
```

## 5. 为什么最后要乘 V

`QK^T` 只告诉我们“该看谁”，还没有真正拿到信息。

经过 softmax 后得到注意力权重：

$$
A = softmax(\frac{QK^T}{\sqrt{d_k}})
$$

其中 `A` 的每一行都是一组权重。

然后用这些权重去加权求和 Value：

$$
Z = AV
$$

也就是完整公式：

$$
Attention(Q,K,V) = softmax(\frac{QK^T}{\sqrt{d_k}})V
$$

直观理解：

```text
QK^T：决定看谁
softmax：决定看多少
乘 V：把看到的信息汇总回来
```

## 6. 一个小例子

假设当前 token 是 `journey`，它对所有 token 的注意力权重是：

```text
Your:    0.10
journey: 0.20
starts:  0.60
step:    0.10
```

那么当前 token 的上下文向量就是：

```text
context =
0.10 * V_Your
+ 0.20 * V_journey
+ 0.60 * V_starts
+ 0.10 * V_step
```

这个 context vector 不是某一个 token 的原始向量，而是根据上下文重新混合出来的新表示。

所以自注意力不是简单地“找一个最相关的词”，而是：

```text
按照相关程度，把多个 token 的信息混合起来。
```

## 7. 和相关系数的相似与不同

相似点：

```text
Q 和 K 的点积都在衡量两个向量是否方向相近。
方向越相近，分数越大，注意力越强。
```

不同点：

- 相关系数通常是统计意义上的固定度量。
- Q/K/V 是模型通过训练学出来的表示。
- 注意力分数不是最终目标，它只是中间权重。
- 最终输出来自对 V 的加权求和。

所以更准确地说：

```text
QK^T 类似“可学习的相关性打分”。
```

## 8. 为什么 Q/K/V 是可训练的

如果直接用原始 embedding 算注意力，模型只能使用人一开始给它的表示空间。

但语言里的关系很复杂：

- 指代关系：`it` 指向哪个名词？
- 修饰关系：形容词修饰哪个名词？
- 语法关系：主语和谓语如何对应？
- 语义关系：哪些词在意思上更相关？

让 `W_q`、`W_k`、`W_v` 可训练，就等于让模型自己学习：

```text
什么样的问题应该被提出
什么样的特征适合被匹配
什么样的信息应该被传递
```

这也是注意力机制强大的地方：相关性不是人工写死的，而是从数据里学出来的。

## 9. 对应代码

在自注意力代码里，通常会看到：

```python
keys = x @ W_key
queries = x @ W_query
values = x @ W_value

attn_scores = queries @ keys.T
attn_weights = softmax(attn_scores / keys.shape[-1] ** 0.5)
context_vec = attn_weights @ values
```

逐行理解：

```text
x @ W_query：把 token 变成“提问者”
x @ W_key：把 token 变成“索引标签”
x @ W_value：把 token 变成“信息内容”
queries @ keys.T：每个提问者和所有索引标签算匹配分数
softmax：把匹配分数变成权重
attn_weights @ values：按权重汇总真正的信息内容
```

## 10. 一句话总结

Q/K/V 的设计，是为了把“找信息”和“提供信息”分开：

```text
Q：我要找什么
K：我是否值得被你找到
V：你找到我以后，我给你什么
```

它们之间的乘法关系可以记成：

```text
Q 和 K 相乘，得到注意力权重；
注意力权重再乘 V，得到上下文表示。
```

也就是：

```text
先匹配，再取内容。
```
