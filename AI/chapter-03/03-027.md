# Time Series Foundation Model 入门

时间序列预测的目标是：给定一段历史观测值，预测未来若干步的值。

传统方法通常需要为每个数据集单独建模，例如 ARIMA、Prophet、LSTM、Transformer 等。Time Series Foundation Model 则更接近大语言模型的用法：模型先在大量不同领域的时间序列上预训练，然后在新序列上直接做 zero-shot forecasting。

这篇笔记整理几个常见的开源时间序列基础模型，并用同一段玩具序列做一个最小对比。

配套代码见：

- [time series model - code](03-028.ipynb)

## 1. TimesFM

TimesFM 是 Google Research 发布的时间序列基础模型。它的核心特点是：

- 面向 univariate forecasting，也就是单变量时间序列预测
- 支持 zero-shot 推理，不需要针对当前序列重新训练
- TimesFM 2.5 支持更长 context，并提供 point forecast 和 quantile forecast

最小推理形式大致是：

```python
model = timesfm.TimesFM_2p5_200M_torch.from_pretrained(
    "google/timesfm-2.5-200m-pytorch"
)
model.compile(timesfm.ForecastConfig(...))

point_forecast, quantile_forecast = model.forecast(
    horizon=12,
    inputs=[context],
)
```

直观理解：TimesFM 把历史序列切成 patch/token，然后像 decoder-only 模型一样生成未来 patch。

---

## 2. Chronos

Chronos 是 Amazon Science 的时间序列基础模型系列。

它有几个分支：

- Chronos：早期版本，把连续值缩放、量化成 token，再用语言模型式结构预测未来 token
- Chronos-Bolt：更快的 patch-based 版本
- Chronos-2：更新版本，支持 univariate、multivariate、covariate-informed forecasting

Chronos-2 的 Python 接口比较接近 dataframe workflow：

```python
pipeline = Chronos2Pipeline.from_pretrained("amazon/chronos-2", device_map="cpu")

pred_df = pipeline.predict_df(
    context_df,
    prediction_length=12,
    quantile_levels=[0.1, 0.5, 0.9],
    id_column="id",
    timestamp_column="timestamp",
    target="target",
    freq="D",
)
```

输出里通常包含：

- `predictions`：点预测
- `0.1`、`0.5`、`0.9`：不同分位数预测

## 3. Lag-Llama

Lag-Llama 是一个基于 decoder-only Transformer 的概率预测模型，主要面向 univariate probabilistic forecasting。

它的名字里有 Lag，是因为它会显式使用一组滞后项作为输入特征：

```text
t-1, t-7, t-30, ...
```

它不是只输出一个确定值，而是输出未来分布的 samples。我们可以从 samples 里取：

- mean：点预测
- quantile(0.1)：下界
- quantile(0.9)：上界

推理流程通常是：

```python
ckpt = torch.load("lag-llama.ckpt", map_location="cpu", weights_only=False)
estimator = LagLlamaEstimator(...)
predictor = estimator.create_predictor(...)
forecast = next(forecast_it)
```

Lag-Llama 当前生态更偏研究代码风格，依赖 GluonTS 和 checkpoint 文件，使用起来比 TimesFM、Chronos 稍重一些。

---

## 4. Moirai 2 / Uni2TS

Moirai 是 Salesforce AI Research 的通用时间序列预测模型，Uni2TS 是它对应的库。

Moirai 2.0 相比早期版本更轻量，采用 decoder-only 架构和 quantile forecasting。

最小调用大致是：

```python
model = Moirai2Forecast(
    module=Moirai2Module.from_pretrained("Salesforce/moirai-2.0-R-small"),
    prediction_length=12,
    context_length=96,
    target_dim=1,
    feat_dynamic_real_dim=0,
    past_feat_dynamic_real_dim=0,
)
predictor = model.create_predictor(batch_size=1)
forecast = next(iter(predictor.predict(dataset)))
```

Moirai / Uni2TS 依赖 GluonTS 的 Dataset 和 Predictor 抽象，适合做更系统的评估和 rolling window backtest。

## 5. 一个最小实验

我们构造一段带趋势的正弦序列：

```python
context = np.sin(np.linspace(0, 10, 96)) + np.linspace(0, 0.8, 96)
```

然后让四个模型都预测未来 12 个点：

```text
history length = 96
horizon = 12
```

实验输出：

- 上下 4 个 subplot 分别展示 TimesFM、Chronos、Lag-Llama、Moirai
- 蓝线是历史序列
- 红线是点预测
- 浅红区域是 10%-90% 预测区间

在这段玩具序列上，TimesFM、Chronos、Moirai 的趋势方向比较接近；Lag-Llama 的 zero-shot 输出明显偏高。这不是严格 benchmark，只是帮助理解不同模型的调用方式和输出形态。

## 6. 依赖注意点

这几个模型放在同一个 notebook 里会遇到依赖组合问题：

- Uni2TS 需要 `torch<2.5`
- TimesFM 在当前实验里使用 `torch==2.13.0` 输出正常
- Lag-Llama 的 checkpoint 在新版本 PyTorch 下需要显式 `weights_only=False`

所以配套 notebook 里把 TimesFM 放到一个单独的 `.venv_timesfm` 子环境中运行，再把 JSON 结果传回主 notebook。这样可以让四个模型在同一个实验中完成对比。

---

## 7. 什么时候用哪个

简单经验：

| 模型 | 更适合 |
|---|---|
| TimesFM | 快速做 univariate zero-shot baseline |
| Chronos-2 | 想用 dataframe 接口，后续可能扩展多变量或协变量 |
| Lag-Llama | 想研究概率预测、samples、GluonTS 生态 |
| Moirai 2 / Uni2TS | 想做更系统的模型评估、rolling evaluation、跨数据集实验 |

真实业务里不要只看一条曲线的可视化效果。至少要留出 test split，比较 MASE、sMAPE、RMSE、CRPS 等指标，再看误差是否满足业务目标。
