# Embedding

Embedding 是把文本（或其他数据）映射为一个稠密的浮点向量，使得语义相近的内容在向量空间中距离也近。

```
"如何部署 nginx"      → [0.12, 0.34, 0.67, ...]  768 维
"nginx 安装教程"      → [0.13, 0.35, 0.65, ...]  768 维  ← 距离近
"今天天气怎么样"      → [0.91, 0.02, 0.11, ...]  768 维  ← 距离远
```

---

## 生成流程

```
输入文本
   ↓
Tokenizer（分词 + 转 ID）
  "RAG 是检索增强生成" → [1234, 99, 567, 890, 321]
   ↓
Token Embedding 查表（模型内部）
  每个 ID 取对应的初始向量，得到 N×D 矩阵
   ↓
Transformer（Self-Attention）
  token 之间互相感知上下文，融合语义
   ↓
Mean Pooling
  N 个向量逐维取平均，压成 1×D 向量
   ↓
输出：整句话的 Embedding 向量
```

注意：Tokenizer 只负责切词和转 ID，输出整数序列，不产生向量。向量由 Token Embedding 查表（模型第一层）开始生成。

## 主要差异维度

### 1. 语言支持

`all-MiniLM-L6-v2`（Chroma 默认）是纯英文模型，中文效果极差，必须换模型。

| 场景 | 推荐模型 |
|------|---------|
| 中文 / 中英双语 | BGE（北京智源）、GTE（阿里） |
| 英文，本地部署 | all-MiniLM-L6-v2（快）、E5（效果好） |
| 多语言，云端 | OpenAI text-embedding-3-small |

### 2. 对称 vs 非对称

查询和文档的表达方式通常不同：

```
查询："怎么部署 nginx"        ← 短句，口语
文档："nginx 部署指南第三章"  ← 长段落，正式
```

非对称模型（如 BGE）对查询加特殊前缀，让两者向量更好地对齐：

```python
# BGE：查询加前缀，文档不加
query = "为这个句子生成表示以用于检索相关文章：怎么部署 nginx"
doc   = "nginx 部署指南第三章..."
```

对称模型对两者用相同方式编码，适合语义相似度场景（两句话是否相似）。

### 3. 向量维度

维度越高不一定效果越好，主要影响存储和计算速度：

| 模型 | 维度 | 特点 |
|------|------|------|
| all-MiniLM-L6-v2 | 384 | 轻量快速，纯英文 |
| BGE-base-zh | 768 | 中英均衡 |
| text-embedding-3-small | 1536 | OpenAI，多语言 |
| text-embedding-3-large | 3072 | 效果最好，最贵 |

### 4. 领域专用模型

通用模型在垂直领域效果一般，专用场景建议用对应的微调模型：

| 领域 | 模型 |
|------|------|
| 代码 | CodeBERT、text-embedding-ada-002 |
| 医疗 | BiomedBERT |
| 法律 | 法律领域微调模型 |

---

## 如何选型

```
中文场景                → BGE-large-zh 或 GTE
英文场景，本地部署      → all-MiniLM-L6-v2（快）
追求效果，不介意调 API  → OpenAI text-embedding-3-small
垂直领域                → 领域微调模型，或基于 BGE 自己微调
```

效果对比参考 MTEB 排行榜：https://huggingface.co/spaces/mteb/leaderboard

## MTEB 各类任务头部模型

MTEB（Massive Text Embedding Benchmark）覆盖 8 类任务，不同任务的最佳模型不同。以下为 2025 年初各类任务头部模型：

### 综合排名（Overall）

| 模型 | 机构 | 特点 |
|------|------|------|
| NV-Embed-v2 | NVIDIA | 综合最强，参数量大 |
| gte-Qwen2-7B-instruct | 阿里 | 开源，7B 参数，效果顶尖 |
| SFR-Embedding-2_R | Salesforce | 综合均衡 |
| voyage-large-2-instruct | Voyage AI | 闭源 API，效果强 |
| text-embedding-3-large | OpenAI | 闭源 API，3072 维 |

### 检索（Retrieval）——RAG 最核心的任务

| 模型 | 特点 |
|------|------|
| gte-Qwen2-7B-instruct | 开源最强，适合本地部署 |
| e5-mistral-7b-instruct | 微软，7B 参数 |
| NV-Embed-v2 | NVIDIA，效果最好 |
| bge-en-icl | BAAI，支持 in-context learning |
| voyage-large-2-instruct | 闭源，检索场景表现突出 |

### 语义相似度（STS）

| 模型 | 特点 |
|------|------|
| text-embedding-3-large | OpenAI，STS 场景表现好 |
| bge-large-en-v1.5 | BAAI，开源，效果均衡 |
| e5-large-v2 | 微软，轻量高效 |

### 中文 / 多语言

| 模型 | 机构 | 维度 | 特点 |
|------|------|------|------|
| bge-m3 | BAAI | 1024 | 支持 100+ 语言，中英最强开源 |
| gte-multilingual-base | 阿里 | 768 | 多语言，轻量 |
| multilingual-e5-large | 微软 | 1024 | 多语言均衡 |
| text-embedding-3-small | OpenAI | 1536 | 闭源，多语言，性价比高 |

### 轻量 / 本地快速推理

| 模型 | 维度 | 特点 |
|------|------|------|
| all-MiniLM-L6-v2 | 384 | 最快，纯英文，Chroma 默认 |
| bge-small-en-v1.5 | 384 | 英文，效果优于 MiniLM |
| bge-small-zh-v1.5 | 512 | 中文轻量首选 |
| text-embedding-3-small | 1536 | 闭源，多语言，速度快 |

> 注：排名随时更新，以实际查阅 [MTEB 排行榜](https://huggingface.co/spaces/mteb/leaderboard) 为准。
