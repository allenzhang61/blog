## 离线推理（Offline Inference）

最基础的用法：本地批量生成，不启动 HTTP 服务。

```python
from vllm import LLM, SamplingParams

prompts = [
    "Hello, my name is",
    "The president of the United States is",
    "The capital of France is",
    "The future of AI is",
]
sampling_params = SamplingParams(temperature=0.8, top_p=0.95)

llm = LLM(model="facebook/opt-125m")
outputs = llm.generate(prompts, sampling_params)

for output in outputs:
    print(f"Prompt:    {output.prompt!r}")
    print(f"Output:    {output.outputs[0].text!r}")
```

### 核心 API

| 类 / 方法 | 说明 |
|-----------|------|
| `LLM(model=...)` | 加载模型，首次运行自动从 HuggingFace 下载 |
| `SamplingParams` | 控制生成策略：`temperature`、`top_p`、`max_tokens` 等 |
| `llm.generate(prompts, params)` | 批量推理，返回 `List[RequestOutput]` |
| `output.outputs[0].text` | 取第一个候选的生成文本 |

## 两个模型的对比实验

### facebook/opt-125m（轻量验证模型）

```python
llm = LLM(model="facebook/opt-125m")
```

**适合场景**：环境验证、pipeline 测试，不关注生成质量。

**资源消耗**：

| 指标 | 数值 |
|------|------|
| 模型显存 | 0.24 GB |
| KV Cache（默认 92% 利用率） | 20.87 GB |
| 推理速度 | ~248 tokens/s |
| 首次启动 | ~20s（含 CUDA Graph 编译） |

**生成示例**：

```
Prompt:    'The capital of France is'
Output:    " starting to struggle to recover from the French financial crisis..."
# 质量差，随机拼凑，仅用于测试
```

### Qwen/Qwen3.5-9B（生产级模型）

9B 参数模型权重占 17.65 GB，接近 RTX 4090（24GB）上限，需要限制上下文长度和 CUDA Graph 捕获大小才能装入。

```python
llm = LLM(
    model="Qwen/Qwen3.5-9B",
    download_dir="/workspace/models",   # 指定本地缓存目录
    max_model_len=8192,                 # 限制上下文长度，减少 KV Cache 需求
    max_num_seqs=8,                     # 限制并发序列数
    gpu_memory_utilization=0.90,
    compilation_config={
        "cudagraph_capture_sizes": [1, 2, 3, 4, 5, 6, 7, 8]
        # 默认会捕获 ~86 个 size，此处压缩到 8 个，节省约 200MB 显存
    },
)
```

**资源消耗**：

| 指标 | 数值 |
|------|------|
| 模型显存 | 17.65 GB |
| KV Cache（max_model_len=8192） | 1.41 GB |
| 推理速度 | ~30 tokens/s |
| 首次启动 | ~3min（torch.compile 编译耗时） |
| 二次启动 | 快（编译结果缓存到 `/workspace/.vllm_cache`） |

**生成示例**：

```
Prompt:    'The capital of France is'
Output:    'Paris, which is known for its iconic landmarks and rich history.'

Prompt:    'The future of AI is'
Output:    "open-ended. We don't know what the future of AI will be."
```

### Qwen3.5-9B（24GB 显卡）

```python

import os

os.environ["PYTORCH_CUDA_ALLOC_CONF"] = "expandable_segments:True"

    "The capital of France is",

        max_model_len=8192,                     # 限制上下文长度，为 KV Cache 腾空间
        max_num_seqs=8,                         # 限制并发序列数
        gpu_memory_utilization=0.90,
        compilation_config={
            "cudagraph_capture_sizes": [1, 2, 3, 4, 5, 6, 7, 8],
            # 默认捕获 ~86 个 size，压缩到 8 个节省约 200MB 显存
        },

    print("\nGenerated Outputs:\n" + "-" * 60)
    for output in outputs:
        print(f"Prompt:    {output.prompt!r}")
        print(f"Output:    {output.outputs[0].text!r}")
        print("-" * 60)

if __name__ == "__main__":
    main()
```

运行：

```bash
python3 basic_qwen.py
```

> 首次运行需要 torch.compile 编译约 3 分钟，编译结果缓存到 `/workspace/.vllm_cache`，第二次启动明显更快。

## 常见问题

**Q：显存不够，OOM 报错？**

两个方向排查：
1. 减少 `max_model_len`（直接降低 KV Cache 用量）
2. 减少 `cudagraph_capture_sizes`（减少 CUDA Graph 开销）

```python
# 最保守配置
LLM(
    model="...",
    max_model_len=4096,
    compilation_config={"cudagraph_capture_sizes": [1, 2, 4, 8]},
    enforce_eager=True,   # 完全跳过 CUDA Graph，省显存但推理略慢
)
```

**Q：vLLM 版本与 CUDA 驱动不兼容？**

新版 vLLM（0.23.0+）需要 CUDA 13.x 驱动（驱动版本 ≥ 570）。旧驱动（CUDA 12.x）需降级到 vLLM 0.6.x 并搭配 PyTorch cu121/cu124。

**Q：`spawn` multiprocessing 警告？**

vLLM 检测到主进程已初始化 CUDA 时，强制用 `spawn` 模式启动 EngineCore 子进程。这是正常行为，不影响运行。若遇到子进程 import 卡死，设置 `OMP_NUM_THREADS=1` 可规避 OpenBLAS 线程竞争问题。

```bash
OMP_NUM_THREADS=1 python3 basic.py
```
