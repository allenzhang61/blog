# vLLM、SGLang、TensorRT-LLM 性能对比

## 概述

| 框架 | 开发方 | 首发时间 | 定位 |
|------|--------|----------|------|
| vLLM | UC Berkeley | 2023.06 | 通用 LLM 推理服务，易用性优先 |
| SGLang | Stanford / LMSYS | 2024.01 | 结构化生成 + 高吞吐，复杂 workflow 优先 |
| TensorRT-LLM | NVIDIA | 2023.10 | NVIDIA GPU 极致性能，硬件深度优化 |

---

## 核心技术对比

### KV Cache 管理

**vLLM — PagedAttention**

- 将 KV Cache 分成固定大小的 Page（类似操作系统的内存分页）
- 不同请求可以共享 KV Cache 中的 Prefix（通过 Copy-on-Write）
- 避免了传统连续内存分配导致的碎片浪费

```
Request A: [Prompt tokens] → [Page 1][Page 2][Page 3]
Request B: [同 Prompt]    → [Page 1][Page 2][Page 4]  ← 共享 Page 1/2
```

**SGLang — RadixAttention**

- 用 Radix Tree（基数树）管理 KV Cache
- 自动识别请求间的公共前缀，最大化 Prefix 复用
- 对多轮对话、few-shot 场景效果显著（相同 system prompt 只算一次）

```
/root
  └─ [System Prompt A] ← 所有使用该 System Prompt 的请求共享
       ├─ [Turn 1a][Turn 2a]
       └─ [Turn 1b][Turn 2b]
```

**TensorRT-LLM — Paged KV Cache + CUDA 内核融合**

- 同样实现了 Paged KV Cache
- 差异在于将 Attention 计算、KV Cache 读写等操作融合进自定义 CUDA Kernel
- 配合 TensorRT 的图优化（layer fusion、kernel auto-tuning），延迟更低

---

### Batching 策略

| 策略 | vLLM | SGLang | TensorRT-LLM |
|------|------|--------|--------------|
| Continuous Batching | ✅ | ✅ | ✅ |
| Chunked Prefill | ✅ | ✅ | ✅ |
| Dynamic Scheduling | ✅ | ✅（更激进） | ✅ |
| Prefix Caching | ✅（Automatic Prefix Caching） | ✅（RadixAttention） | ✅（需配置） |

**Chunked Prefill** 将长 Prompt 的 Prefill 拆分成多个 Chunk，与 Decode 步骤交叉执行，降低首 Token 延迟（TTFT）的同时保持吞吐。

### 量化支持

| 量化方式 | vLLM | SGLang | TensorRT-LLM |
|----------|------|--------|--------------|
| FP8 W8A8 | ✅ | ✅ | ✅ |
| INT8 W8A8 | ✅ | ✅ | ✅ |
| INT4 GPTQ | ✅ | ✅ | ✅ |
| INT4 AWQ | ✅ | ✅ | ✅ |
| FP4 NVFP4 | ❌ | ❌ | ✅（Blackwell） |
| MX FP8 | 部分 | 部分 | ✅ |

TensorRT-LLM 对 NVIDIA 新硬件特性（如 H100 的 FP8 Tensor Core、B200 的 NVFP4）支持最快最完整。

### Prefix Cache 命中场景（相同 System Prompt，并发 100）

```
SGLang（RadixAttention）  ████████████████████  提升最显著，~2x throughput vs 无 cache
```

**结论**：
- 纯吞吐和低延迟：TensorRT-LLM 在 NVIDIA GPU 上最强
- 有大量 Prefix 复用的场景（Agent、多轮对话）：SGLang 优势明显
- 工程快速落地、模型兼容性：vLLM 最成熟

## 结构化输出

**SGLang** 原生支持结构化生成（JSON Schema、正则约束），通过 XGrammar/Outlines 集成，生成时直接约束 logits，不需要后处理重试。

**vLLM** 也支持 Guided Decoding（via Outlines/LM-Format-Enforcer），能力相近，但 SGLang 的整合更深。

**TensorRT-LLM** 目前原生支持较弱，通常需要外部 wrapper。

## 部署与生态

| 维度 | vLLM | SGLang | TensorRT-LLM |
|------|------|--------|--------------|
| 安装复杂度 | 低（`pip install vllm`） | 低（`pip install sglang`） | 高（需编译或用官方容器） |
| OpenAI 兼容 API | ✅ 完整 | ✅ 完整 | 需 Triton 或自行封装 |
| Kubernetes / 云原生 | ✅ 成熟（KServe、Ray Serve） | ✅ 成熟 | 有限 |
| 模型支持广度 | 最广（Hugging Face 生态） | 广 | 主流模型，需转换引擎 |
| 社区活跃度 | 极高 | 高 | 中（NVIDIA 主导） |
| 商业支持 | 无（Apache 2.0） | 无（Apache 2.0） | NVIDIA 官方 |

**TensorRT-LLM 的引擎构建**：使用前需先将模型转换为 TRT 引擎，这一步耗时（数十分钟），且引擎与 GPU 型号绑定，迁移时需重新构建。

## 适用场景推荐

| 场景 | 推荐框架 | 原因 |
|------|----------|------|
| 快速原型 / 研究 | vLLM | 安装简单，模型兼容性最好 |
| 生产级 API 服务（通用） | vLLM 或 SGLang | 成熟、社区大、易运维 |
| Agent / 多轮对话 / RAG | SGLang | RadixAttention 对 Prefix 复用效果最好 |
| 结构化输出（JSON/语法约束） | SGLang | 原生支持更深 |
| NVIDIA 生产集群，极致性能 | TensorRT-LLM | 硬件利用率最高 |
| 在线推理 SLA 极严（< 20ms P99） | TensorRT-LLM | 最低延迟 |
| MoE 大模型（Mixtral、DeepSeek） | SGLang / TensorRT-LLM | Expert Parallel 优化更好 |

---

## 总结

```
易用性   vLLM > SGLang > TensorRT-LLM
吞吐量   TensorRT-LLM > SGLang > vLLM（NVIDIA GPU）
延迟     TensorRT-LLM ≈ SGLang > vLLM
缓存复用 SGLang > vLLM > TensorRT-LLM
兼容性   vLLM > SGLang > TensorRT-LLM
```

三者均在快速迭代，差距正在缩小。实际选型建议以最新 Benchmark 为准，并结合自身业务场景（是否有大量相同 Prefix、是否需要结构化输出、是否追求极致硬件性能）做决策。
