# Chroma 向量数据库介绍

## 是什么

Chroma 是一个开源的向量数据库，专为 AI 应用设计，核心用途是存储和检索文本/多模态的 Embedding 向量。

```
文档 → Embedding 模型 → 向量 → 存入 Chroma → 查询时按语义相似度召回
```

**三种运行模式：**

| 模式 | 用途 |
|------|------|
| 内存模式（默认） | 开发调试，进程退出数据消失 |
| 持久化模式 | 数据写入本地磁盘，重启后保留 |
| Client-Server 模式 | 多进程/多服务共享，生产部署 |

## 核心概念

```
Chroma
  └── Collection（集合，类似数据库的表）
        └── Document（原始文本）
        └── Embedding（向量，可自动生成或手动传入）
        └── Metadata（结构化字段，支持过滤）
        └── ID（唯一标识）
```

一个 Collection 对应一个语义检索空间，不同业务场景建不同 Collection。

## 核心原理

### 1. Embedding 存储

文档写入时：

```
文档文本
   ↓
Embedding 函数（默认 all-MiniLM-L6-v2，也可接 OpenAI / 自定义）
   ↓
float32 向量（如 384 维）
   ↓
写入 HNSW 索引 + SQLite 元数据
```

#### 一句话如何变成 384 维向量

以 `"RAG 是检索增强生成"` 为例：

```
第一步：Tokenizer（分词 + 转 ID）
"RAG 是检索增强生成"
   ↓
["RAG", "是", "检索", "增强", "生成"]
   ↓
[1234, 99, 567, 890, 321]   ← token ID（整数），Tokenizer 到此结束

第二步：Token Embedding 查表（模型内部，非 Tokenizer）
  用 ID 去模型权重矩阵里取对应的行，得到初始向量
"RAG"  → [0.12, 0.34, ...]  384 维
"是"   → [0.88, 0.01, ...]  384 维
"检索"  → [0.45, 0.67, ...]  384 维
"增强"  → [0.23, 0.91, ...]  384 维
"生成"  → [0.56, 0.12, ...]  384 维
          ↓
       5 × 384 的矩阵

第三步：加位置编码（Positional Encoding）
  token 向量本身没有顺序信息，叠加位置向量告知模型每个 token 的位置
  token[0] 的向量 += 位置[0] 的向量
  token[1] 的向量 += 位置[1] 的向量
          ↓
       仍然是 5 × 384，但每个 token 知道自己在第几位

第四步：N 层 Transformer 块（核心，重复 N 次）
  每层内部两个子步骤：

  ① Self-Attention：每个 token 和其他所有 token 交互
    生成 Q（我想找什么）、K（我有什么）、V（我携带的信息）：
      Q = X · Wq
      K = X · Wk
      V = X · Wv
    计算注意力权重（5×5 相关性矩阵）：
             RAG   是   检索  增强  生成
      RAG  [ 0.8  0.1  0.6  0.3  0.5 ]
      是   [ 0.2  0.9  0.3  0.1  0.2 ]
      ...
    加权求和 V，得到每个 token 融合了全句语义的新向量

  ② FFN（前馈网络）：对每个 token 做非线性变换，增强表达能力

  重复 N 层（all-MiniLM-L6-v2 是 6 层，bge-large 是 24 层）
          ↓
       仍然是 5 × 384，但每个向量都充分融合了上下文信息

第五步：Mean Pooling
把 5 个 384 维向量逐维取平均
  第 1 维：(0.12 + 0.88 + 0.45 + 0.23 + 0.56) / 5 = 0.448
  第 2 维：(0.34 + 0.01 + 0.67 + 0.91 + 0.12) / 5 = 0.410
  ...
          ↓
       1 × 384 的向量  ← 整句话的向量
```

all-MiniLM-L6-v2 用 Mean Pooling：所有 token 向量逐维求平均，压成一个向量代表整句话的语义。模型的"能力"全部在权重里（$W_q, W_k, W_v$ 及 FFN 参数），这些权重训练时学出来，目标是让语义相近的句子生成的向量距离更近。

### 2. 向量检索：HNSW

Chroma 使用 **HNSW（Hierarchical Navigable Small World）** 算法做近似最近邻（ANN）检索。

#### 数据结构：多层图

```
Layer 2（最稀疏，长跳）：
  A ─────────────────── E

Layer 1（中等密度）：
  A ────── C ─────────── E

Layer 0（最密集，所有节点）：
  A ── B ── C ── D ── E ── F ── G
```

每个节点在 Layer 0 一定存在，是否出现在更高层随机决定（概率递减，越高层越稀疏）。

#### 查询过程

```
Step 1：从最高层入口节点出发
  Layer 2: 当前在 A，检查邻居距离 → 跳到更近的节点 E

Step 2：下沉到 Layer 1，继续贪心搜索
  Layer 1: 当前在 E，检查邻居 → 跳到 C（更近）

Step 3：下沉到 Layer 0，精确搜索
  Layer 0: 当前在 C，检查所有邻居 → D 最近，返回 D
```

```
暴力搜索：和数据库里 100万 个向量逐个算距离 → O(n)
HNSW：   高层大步跳跃缩小范围，Layer 0 搜一小片 → O(log n)
         准确率通常 > 95%，速度快 100x 以上
```

高层的长边是"捷径"，让任意两个向量之间通过少量跳跃就能到达，这是"小世界"特性的来源（借鉴六度分隔理论）。

#### 相似度度量：如何计算邻近距离

Chroma 支持三种方式：

**余弦相似度（默认）**

$$
\cos(\theta) = \frac{A \cdot B}{|A| \times |B|}
$$

以 $A = [1, 2, 3]$，$B = [2, 4, 6]$ 为例：

$$
A \cdot B = 1 \times 2 + 2 \times 4 + 3 \times 6 = 28
$$

$$
|A| = \sqrt{1^2 + 2^2 + 3^2} = \sqrt{14} \approx 3.74, \quad |B| = \sqrt{56} \approx 7.48
$$

$$
\cos(\theta) = \frac{28}{3.74 \times 7.48} \approx 1.0 \quad \text{（完全相似）}
$$

看方向，不看长度。短句和长句表达同一语义时，余弦相似度仍接近 1。

**欧氏距离（L2）**

$$
d = \sqrt{(A_1 - B_1)^2 + (A_2 - B_2)^2 + \cdots + (A_n - B_n)^2}
$$

以 $A = [1, 2]$，$B = [4, 6]$ 为例：

$$
d = \sqrt{(1-4)^2 + (2-6)^2} = \sqrt{9 + 16} = 5
$$

看空间距离，距离越小越相似。适合图像特征、坐标类数据。

**内积（ip）**

$$
A \cdot B = A_1 B_1 + A_2 B_2 + \cdots + A_n B_n
$$

值越大越相似。同时考虑方向和向量模长，适合已归一化的向量和推荐系统。

**三者对比**

| | 余弦 | L2 | 内积 |
|--|------|----|------|
| 关注 | 方向 | 空间距离 | 方向 + 大小 |
| 受向量长度影响 | 否 | 是 | 是 |
| 文本场景 | 首选 | 不适合 | 归一化后可用 |
| 图像/坐标 | 一般 | 首选 | 一般 |

相似度度量支持：`cosine`（默认）、`l2`、`ip`（内积）

### 3. 混合过滤

查询时可同时做向量检索 + 元数据过滤：

```python
collection.query(
    query_texts=["如何提升稳定性"],
    n_results=5,
    where={"category": "ops"},        # 元数据过滤（精确匹配）
    where_document={"$contains": "故障"}  # 文档内容过滤
)
```

先向量召回，再元数据过滤，两者结合提高精度。

## 快速上手

```python
import chromadb

# 持久化到本地
client = chromadb.PersistentClient(path="./chroma_db")

# 创建集合
collection = client.get_or_create_collection(
    name="knowledge_base",
    metadata={"hnsw:space": "cosine"}  # 相似度度量
)

# 写入文档（Chroma 自动生成 Embedding）
collection.add(
    documents=[
        "RAG 是检索增强生成技术",
        "Chroma 是轻量级向量数据库",
        "HNSW 是近似最近邻算法",
    ],
    metadatas=[
        {"category": "rag"},
        {"category": "db"},
        {"category": "algorithm"},
    ],
    ids=["doc1", "doc2", "doc3"]
)

# 查询
results = collection.query(
    query_texts=["什么是向量数据库"],
    n_results=2
)
print(results["documents"])
# [['Chroma 是轻量级向量数据库', 'RAG 是检索增强生成技术']]
```

| | Chroma | pgvector | Pinecone | Milvus |
|--|--------|----------|----------|--------|
| 部署复杂度 | 极低 | 低（有 PG） | 零（云托管） | 高 |
| 适合规模 | 百万以下 | 千万以下 | 不限 | 亿级 |
| 持久化 | SQLite | PostgreSQL | 云存储 | 分布式 |
| 生产可用性 | 一般 | 好 | 好 | 好 |
| 入门难度 | ★☆☆☆☆ | ★★☆☆☆ | ★★☆☆☆ | ★★★★☆ |

**定位**：Chroma 是学习和原型阶段的首选，生产环境大规模场景建议迁移到 pgvector 或 Pinecone。
