# HNSW 算法介绍

HNSW（Hierarchical Navigable Small World）是向量数据库中最主流的近似最近邻（ANN，Approximate Nearest Neighbor）索引算法，被 Chroma、Weaviate、Faiss 等广泛使用。

---

## 问题背景

向量检索的目标：给定查询向量 $Q$，在数据库中找到与之距离最近的 $k$ 个向量。

```
暴力搜索：和数据库里所有向量逐个计算距离 → 复杂度 O(n)
          100 万向量、384 维 → 每次查询需要计算 384 × 100万 次乘法，太慢

目标：用近似最近邻（ANN，Approximate Nearest Neighbor）换取速度，允许极小的精度损失
```

---

## 与跳表的关系

HNSW 外形上很像跳表，但本质不同。

**跳表**靠**排序**导航：Layer 0 是有序链表，高层是快速通道，靠大小比较跳跃。

**HNSW** 靠**近邻图**导航：Layer 0 是近邻图，没有全局顺序，靠向量距离贪心游走。

```
跳表 Layer 0（有序链表）：
  1 ── 3 ── 7 ── 12 ── 18 ── 25
  按值排序，查找时向右走直到超过目标

HNSW Layer 0（近邻图）：
  A ── B
  |  ╲ |
  C ── D ── E
  无全局顺序，每个节点只和向量空间里距离近的邻居相连
```

---

## 数据结构

多层图，每层都是一张近邻图：

```
Layer 2（最稀疏）：
  A ─────────────── E

Layer 1（中等密度）：
  A ────── C ─────── E
           |
           D

Layer 0（最密集，包含所有节点）：
  A ── B ── C ── D ── E ── F ── G
       |         |
       C ─────── F
```

- **Layer 0**：包含全部节点，每个节点连接 $M$ 个最近邻，构成稠密近邻图
- **高层**：节点随机晋升（概率递减），连接更少的邻居，构成稀疏长跳图
- 节点是否出现在第 $l$ 层，由概率 $p^l$ 决定（$p < 1$，默认 $p = 1/\ln(M)$）

---

## 构建过程

插入新节点 $X$ 时：

```
Step 1：随机决定 X 出现在哪几层
  掷骰子，比如 X 出现在 Layer 0 和 Layer 1

Step 2：从最高层入口节点出发，贪心搜索
  在 Layer 2、Layer 1 中各找到距 X 最近的节点，作为下沉起点

Step 3：在 X 存在的每一层，找最近的 M 个邻居，双向连边
  Layer 1: X ── A,  X ── C
  Layer 0: X ── A,  X ── B,  X ── C,  X ── D
```

Layer 0 没有排序，只保证：**每个节点的邻居是它在向量空间里距离最近的节点**。

---

## 查询过程

查找与查询向量 $Q$ 最近的节点：

```
Step 1：从最高层入口节点出发（固定的全局入口）
  Layer 2: 当前在 A → 检查 A 的邻居 → 跳到离 Q 更近的 E

Step 2：下沉到 Layer 1，继续贪心游走
  Layer 1: 当前在 E → 检查邻居 → 跳到 C

Step 3：下沉到 Layer 0，精确搜索
  Layer 0: 当前在 C → 检查所有邻居 → 返回最近的 D
```

每一步都做**贪心选择**：移动到所有邻居中离 $Q$ 最近的那个，直到无法再近为止。

---

## 为什么叫"小世界"

借鉴**六度分隔理论**：任意两人之间最多经过 6 个中间人。

HNSW 的图构建保证了：**任意两个节点之间，通过少量跳跃就能到达**。高层的长边充当"捷径"，使图具备小世界（Small World）特性，避免陷入局部最优。

---

## 复杂度

| 操作 | 复杂度 |
|------|--------|
| 构建索引 | $O(n \log n)$ |
| 单次查询 | $O(\log n)$ |
| 暴力搜索 | $O(n)$ |

查询速度比暴力搜索快 **100x 以上**，准确率通常 **> 95%**。

---

## 关键参数

| 参数 | 含义 | 默认值 | 影响 |
|------|------|--------|------|
| `M` | 每个节点在 Layer 0 的最大邻居数 | 16 | 越大准确率越高，内存和构建时间越大 |
| `ef_construction` | 构建时搜索候选集大小 | 200 | 越大索引质量越好，构建越慢 |
| `ef_search` | 查询时搜索候选集大小 | 10 | 越大召回率越高，查询越慢 |

调优方向：

```
追求高召回率：调大 ef_search（不影响索引，只影响查询速度）
追求高质量索引：调大 ef_construction 和 M（影响构建时间和内存）
```

## 距离度量

HNSW 支持多种距离度量，决定"邻近"的定义：

**余弦相似度**（文本语义场景首选）

$$
\cos(\theta) = \frac{A \cdot B}{|A| \times |B|}
$$

**欧氏距离 L2**（图像、坐标场景）

$$
d = \sqrt{\sum_{i=1}^{n}(A_i - B_i)^2}
$$

**内积 IP**（归一化向量、推荐系统）

$$
A \cdot B = \sum_{i=1}^{n} A_i B_i
$$

## 局限性

- **不支持动态删除**：删除节点需要标记为删除，不能真正从图中移除，否则破坏图结构
- **内存占用高**：所有向量和图结构必须常驻内存
- **构建慢**：相比 IVF 等索引，构建时间更长
- **近似非精确**：极少数情况下可能漏掉真正的最近邻
