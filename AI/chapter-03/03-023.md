## 坐标轴解读

**X 轴：Recall（召回率）**

$$
\text{Recall} = \frac{\text{ANN 算法找到的真正最近邻数量}}{k}
$$

以 $k=10$ 为例，暴力搜索能找到真正最近的 10 个，ANN 算法找到了其中 9 个，则 Recall = 0.9。Recall = 1.0 表示结果与暴力搜索完全一致。

**Y 轴：Queries per second，QPS（每秒查询数）**

单位时间内能处理多少次查询，越高越快。Y 轴为**对数坐标**。

## 如何看图

**右上角是最好的**：召回率高（准）且 QPS 高（快）。

每条曲线代表一个算法，通过调整参数（如 `ef_search`）在召回率和速度之间权衡，参数变化形成一条曲线而不是一个点。曲线越靠右上角，综合性能越好。

## qsgngt算法介绍

目前看性能最好的是 qsgngt：https://github.com/WPJiang/HWTL_SDU-ANNS

qsgngt 综合了三个已有算法的思路：**NGT-qg**（Yahoo Japan）、**Efanna**、**SSG（Satellite System Graph）**，通过三阶段构建索引。

### 三阶段构建

#### 阶段一：AKNNG（Approximate K-Nearest Neighbor Graph）

目标：快速为每个节点找到 K 个近似最近邻，构建初始图。

```
Step 1：随机 KD 树初始化
  把所有向量随机投影，建多棵 KD 树
  每个节点在树中找到近邻候选集

  向量空间
  ┌─────────────────┐
  │    *   *        │  随机超平面切割
  │  * │ *   *      │  左侧归一组
  │    │    *│*     │  右侧再切割
  │  * │  *  │  *   │
  └─────────────────┘
  同一叶节点的向量互为候选近邻

Step 2：NN-Descent 迭代精化
  核心思想："我的邻居的邻居，也可能是我的邻居"

  初始图：A → {B, C}，B → {C, D}
  迭代：
    检查 A 的邻居 B 的邻居 {C, D}
    若 dist(A, D) < A 当前最远邻居 → 替换
    反向传播：D 也把 A 加入候选

  重复迭代直到图不再变化（收敛）
```

关键参数：K（邻居数）、iter（迭代次数）、L/S/R（精度控制）

---

#### 阶段二：SG（Space Graph，基于 SSG）

目标：对 AKNNG 做剪枝和重构，让图导航更稳定，避免贪心搜索陷入局部最优。

核心问题：AKNNG 的邻居都堆在一起，方向太集中，搜索时容易走死路。

```
AKNNG 的邻居（差）：         SG 的邻居（好）：
       B                           B
      /                           /
A -- C   ← 全在同侧              A        ← 分散在各方向
      \                           \
       D                      E    C
                                    \
  B、C、D 方向接近，                  D
  换一个方向的查询就找不到
```

**角度剪枝（MRNG 策略）**：

```
对节点 u，候选邻居按距离排序，逐个审核：

for 候选节点 v（按 dist(u,v) 从近到远）：
    accept = True
    for 已接受的邻居 w：
        if angle(v, u, w) < θ：  ← v 和 w 方向太近
            accept = False        ← 丢弃 v
            break
    if accept：
        加入 u 的邻居列表
    if 邻居数 >= outdegree：
        break
```

$$
\angle(v, u, w) < \theta \Rightarrow \text{丢弃 } v
$$

结果：每个节点的邻居在空间中均匀分散，任意方向的查询都能找到出路。

同时控制：`outdegree`（每节点最多出边数）、`indegree`（最多入边数），防止某些节点成为"孤岛"。

---

#### 阶段三：QSG（Quantized Space Graph，基于 NGT-qg）

目标：对 SG 的向量做量化压缩，用近似距离加速候选筛选，同时保持高召回率。

**乘积量化（Product Quantization，PQ）**：

```
原始向量（384 维 float32 = 1536 字节）
   ↓ 切分为 M 个子向量（如 M=48，每段 8 维）
[子向量1][子向量2]...[子向量48]
   ↓ 每段独立训练 256 个聚类中心（codebook）
   ↓ 每段只存聚类中心的编号（1 字节）
压缩后：48 字节  ← 压缩 32 倍
```

**搜索流程**：

```
查询向量 Q
   ↓
Step 1：预计算距离表
  Q 的每段子向量 与 对应 codebook 的 256 个中心逐一算距离
  结果存入查找表（只算一次）

Step 2：图上游走时用近似距离快速筛选
  候选节点的近似距离 = 查表累加各段距离
  代替全精度距离计算，速度提升数倍

Step 3：对最终候选集用原始向量精确重排
  只对 top-N 候选做精确距离计算
  保证召回率
```

$$
\tilde{d}(Q, X) = \sum_{m=1}^{M} d(Q_m,\ \text{codebook}_m[\text{code}_m(X)])
$$

代价：引入量化误差，召回率略有损失，靠最终重排补回来。

### 与 HNSW 的区别

| | HNSW | qsgngt |
|--|------|--------|
| 图结构 | 多层图 | 单层高质量图 |
| 构建方式 | 逐点增量插入 | 三阶段全量批处理 |
| 构建时间 | 快 | 慢（AKNNG 迭代 + SG 剪枝 + PQ 训练） |
| 支持增量写入 | 是 | 否，需全量重建 |
| 量化压缩 | 无 | 有（QSG 阶段，压缩 32x） |
| 查询性能 | 好 | 更好（高召回率区间 QPS 更高） |
| 调参复杂度 | 低 | 高 |
| 内存占用 | 高 | 低（量化后向量更小） |

**核心取舍**：qsgngt 用**一次性的高构建成本**换取**持续的高查询性能**。

```
适合 qsgngt：
  数据相对静态（知识库、商品库，每天全量更新一次）
  查询 QPS 要求高，构建可以离线完成

适合 HNSW：
  数据实时写入（每秒有新向量插入）
  数据量中等（百万级），构建时间不是瓶颈
  快速上线，调参成本低

行业常见做法：
  实时写入 → HNSW（支持增量）
      ↓ 定期离线重建（每天 / 每周）
  替换为 qsgngt → 提升查询吞吐量
```
